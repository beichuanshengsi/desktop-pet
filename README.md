# 桌面宠物 · Desktop Pet

一只常驻桌面的**线条小狗**，外加**四个**可以一起玩的小游戏，以及一本
**102 张的收集卡册**。Python + PySide6（Qt）实现，只针对 Windows。

当前版本 **v2.6.0**（与 `pet/__init__.py` 的 `__version__` 一致）——
这一版修了**打砖块侧撞把砖块点碎**的判定 bug，卡册加了**「仅看已有」**，
抽卡加了**翻牌动画**；上一版修了游戏中途退出白丢分数的问题（先弹确认框：
结算 / 暂停 / 取消）。逐条更新记录见 **[`CHANGELOG.md`](CHANGELOG.md)**，
项目事实与验收证据见 **[`FACTS.md`](FACTS.md)**。

## 快速开始

依赖已经装好了，直接跑就行。三种方式：

| 方式 | 操作 | 说明 |
|---|---|---|
| 双击 | `run.bat` | 最省事，自动找对解释器，不弹黑框 |
| VS Code | 按 `F5` 选「启动桌宠（main.py）」 | 推荐，能下断点 |
| 命令行 | 见下方 | 想看控制台输出时用 |

```bash
# 命令行运行：必须用装好依赖的那个解释器
C://Users//华硕//.workbuddy//binaries//python//envs//default//Scripts//python.exe main.py
```

> **注意：不要直接敲 `python main.py`。**
> 这台机器 PATH 里的 `python` 是托管**基础**解释器，没装 PySide6，
> 会直接报 `ModuleNotFoundError: No module named 'PySide6'`。
> 依赖都装在 `...\binaries\python\envs\default\` 这个 venv 里，
> `run.bat` 和 VS Code 都已经处理好了路径 —— 用它们就不会踩到这个坑。

想自己另建一套环境的话：

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

首次启动就能直接看到效果 —— 素材随程序自带（现役的在 `custom_pet/`）。
贴图目录若为空，程序会在控制台打印该往哪儿放，**不会**再自动画一套兜底图。

## 素材从哪来

当前形象是**线条小狗**（奶油色、圆头、长垂耳、短腿）。素材是**爱给网下载的 GIF 表情包**，
用 `tools/prep_sticker.py` 拆帧、抠底、统一到 128×128 后落在 `custom_pet/`。

现役素材**逐状态的来源（哪张 GIF、`--scale` 定多少）与复现命令**，写在
**`custom_pet/README.md`** 的表格里 —— 那一版是逐字节复现验证过的。

> **2026-09-22 起不再有"代码画"的内置贴图。**
> 项目早期写过两套程序化生成器（`pet/assetgen.py` 原版奶茶狗 / `pet/assetgen_line.py`
> 线条小狗），连同风格注册表 `pet/styles.py`、入口 `tools/gen_assets.py` 一起删掉了 ——
> 自绘的形象达不到可用质量，正式素材一律用真实图片素材。
> 目录 `assets/pet/` 保留为「内置素材」的落点，但现在里面只有一份 README。

**要换成自己的素材**：见后面「换成你自己的素材」—— 一条 `intake.py` 就能把一批 GIF
自动分派到各动作，不需要先分类、也不需要手工改名。

### 从"代码画"这件事上留下的三条经验

生成器虽然删了，但当时踩出来的判断仍然适用于挑素材：

1. **判断"像不像 / 是不是走路"这类事，量化指标不可靠，最后都得自己看图。**
   指标只配用来缩小候选范围（`tools/review_materials.py` 就是这么定位的）。
2. **素材的读取规则只应该有一份实现。** 脚本随手写个 `glob`，等目录里出现新命名
   （比如多套素材）时必然漏改，而且症状是"图不对"而不是报错，最难查。
3. **朝向、缩放这类属性是"每一套素材"的，不是"整个目录"的。**
   换素材后狗倒着走、或者某套忽然变大，根因都是把逐套属性当成了全局属性。

### 想换成自己的虚拟环境

python -m venv .venv

### 调试时的三个提醒

1. **按 `F5` 弹出「Cannot find Java 1 or higher」** —— 这是**已安装的 Oracle Java 扩展抢了 F5 快捷键**，跟桌宠、跟 Python 都没关系。它的日志里写得很明白：

   ```
   [Oracle.oracle-java]: Java 已注册命令 `workbench.action.debug.start`
   ```

   `workbench.action.debug.start` 就是 F5。这台机器没装 JDK，所以它一按就报错。
   **解决**：扩展面板（`Ctrl+Shift+X`）搜索 `oracle-java` → 齿轮 → 禁用。
   不用 Java 的话，把 `vscjava` 那套（java-pack / java-debug / maven / gradle）一并禁用更省事。
   禁完 F5 就交还给 Python 调试器了。

2. **`F5` 启动了但看不到窗口** —— 桌宠是无边框置顶窗口，可能被其他窗口盖住，
   或者上一次退出时留下了 `show_on_start=false` 的存档。先看系统托盘的图标。

3. **停止调试** —— 桌宠是常驻程序不会自己退出。点 VS Code 的停止按钮，或从托盘菜单退出。
   偶尔会残留进程，任务管理器结束 `python.exe`。

### 解释器路径为什么写死在配置里

`launch.json` 和 `tasks.json` 里的解释器是**完整绝对路径**，没有用
`${command:python.interpreterPath}`。原因是这个变量返回的是"你最近手动选过的那个解释器"，
**优先级高于 `.vscode/settings.json` 里的 `defaultInterpreterPath`**。

本机就踩了这个坑：变量解析成了 `C://Users//华硕//.local//bin//python3.12.exe`
（uv 的 45 KB 垫片，指向 Python 3.12.14），那个环境**没装 PySide6**，一调就是
`ModuleNotFoundError`。写死路径后不再受解释器手动选择影响。

想让 Pylance 的补全也对齐，手动选一次即可：`Ctrl+Shift+P` → `Python: Select Interpreter`
→ 列表里已经有 `default` 这个环境了（靠 `settings.json` 里的 `python.venvPath` 发现）。

## 怎么玩

| 操作 | 效果 |
|---|---|
| 左键拖动 | 把它拎起来，松手会掉下去并站稳（关掉「重力下坠」就停在原地）|
| 左键**甩出去** | 拖着它快速一甩再松手，它会**飞出去、撞到屏幕边弹回来**（详见下节）|
| 左键单击 | 它会蹦一下回应你（关掉「重力下坠」时只演动作、不蹦，否则它会一路飘到天花板）|
| 右键 | 打开菜单：逗它玩 / 去睡一会儿 / 喂一口 / 🛒 小卖部 / 🎒 背包 / 🍅 番茄钟 / 一起玩游戏 / 幼儿模式 / 各种开关 / 左右翻向 / 退出 |
| 托盘图标双击 | 宠物藏起来之后从这里叫回来 |
| 托盘图标右键 | 和右键菜单一样，另加"大小"选项；鼠标悬停能看到状态摘要 |

> **鼠标划过它身上不会有任何反应** —— v2.2.0 把那个"划过弹出状态卡片"撤掉了。
> 状态值只剩右键菜单第一行和托盘 tooltip 两处，都要**你主动去点**。
> 为什么撤：它常驻桌面，鼠标划过是一天几十次的意外动作，每次都弹一张卡片就成了打扰。

### 它现在有「状态」了：饱食 / 心情 / 精力

**这是 v2.0.0 最大的变化** —— 它不再是一张只会动的贴图，而是会饿、会闷、会累。
三个数值都在 **0~100**，随时间自动往下掉（右键菜单和托盘菜单都能看到当前值）：

| 数值 | 怎么涨 | 怎么掉 |
|---|---|---|
| 饱食 | 「喂一口」**每天头一次免费**（+26），之后吃背包里的东西；小卖部买吃的 | 每分钟 -0.21（睡着时 -0.20） |
| 心情 | 「逗它玩」+8；小卖部买玩具球；**睡觉时也在回升**（+0.18/分） | 每分钟 -0.16 |
| 精力 | **只能靠睡觉**（睡着 +6.0/分）；也可以右键**「去睡一会儿」**主动让它睡（v2.4.0）| 每分钟 -0.28 |

（「逗它玩」要花一点精力：**3.3**，玩是有代价的，但不会玩两下就困。
v2.2.1 把它的心情收益从 22 降到了 8 —— 免费陪伴的收益得明显低于花钱的玩具球，
不然"买球"这件事看起来很傻。精力消耗**没跟着降**：「玩一次费多少力」是动作
本身的属性，不是收益的属性。）

两条会**自己动**的行为（不用你操作）：

- **饿了**（饱食 < 30）：它会**自己跑到屏幕正中间**待着，像在讨饭 —— 喂它就回去接着逛。
- **没电了**（精力 < 25）：它会**趴下睡觉**（`sleep_*` 那套贴图），睡到精力 > 82 才醒。
  睡着时戳它一下能把它弄醒，但它精力还低，过一会儿还会接着睡。

### 「去睡一会儿」：第一次能主动安排它休息（v2.4.0）

上面那条"没电了才趴下"意味着：**你不困它就不睡**，精力只能眼看它硬撑到见底。
v2.4.0 在右键菜单里补了一个入口 —— **「去睡一会儿」**，点了它当场趴下。

| | 自然睡（没电了） | 主动小睡（去睡一会儿） |
|---|---|---|
| 什么时候睡 | 精力 < 25 自动 | **你说了算** |
| 睡多久 | 睡到精力 > 82（约 **9.5 分钟**） | 同样睡到 82，但按 **3 倍速** ⇒ 约 **3 分钟** |
| 最短躺多久 | 无 | **至少 1 分钟**（免得精力快满时趴下几秒又起来） |
| 心情 / 饱食 | 一样的账 | **一模一样的账** |

菜单那一行会当场算给你看，比如 `去睡一会儿（睡饱约 2 分钟）`；
三种**点不了**的情况会灰掉并写明原因，而不是点了没反应：

```
去睡一会儿（它已经睡着了）      ← 已经在睡
去睡一会儿（先把它放到地上）    ← 正被拎着 / 正往下掉
去睡一会儿（它不困（精力 95））  ← 精力还足，硬睡只会趴下几秒又起来
```

> **它不多给你任何东西。** 加速的是"整段时间"，所以同样从 E 睡到 82，
> 心情还是回 `0.18×(82−E)/6`、饱食还是掉 `0.20×(82−E)/6` ——
> 跟自然睡**分毫不差**。这一版买到的是**"什么时候睡"的安排权**，不是资源。
> 也正因为不多给资源，它**没有每日次数限制**（睡觉本身就要花掉 1~3 分钟真实时间）。

> 关掉程序期间也照样饿，但**有下限**：回来时不会低于 30；而且最多只按 12 小时算账
> （出门一周和出门半天，扣得一样多）。所以**它不会被饿死**，只会一见面就跟你讨饭。

### 状态在哪看：只有两处，都得你主动点

状态值的显示口**一路收窄**：v2.0.0 只有右键菜单一个 → v2.1.0 一口气开到三个
（菜单 / 面板 / 划过弹出）→ **v2.2.0 收回两个**。

| 想看什么 | 怎么做 | 看到什么 |
|---|---|---|
| 顺手瞄一眼 | 右键它，看**菜单第一行**那两行 | 饱食 / 心情 / 精力 + 金币，就在菜单顶上 |
| 不开程序界面 | 把鼠标停在托盘图标上 | tooltip 里一行状态摘要 |

**鼠标划过它身上不会有任何反应**。原来那个"划过弹一张 178px 的卡片、2 秒后自收"
是 v2.1.0 加的，用了一天发现是打扰 —— 桌宠常驻桌面，鼠标经过它是**一天几十次的意外动作**，
而状态是按分钟级衰减的，不值得每次路过都汇报一次。

> 撤掉之后，背包面板里**不再有状态条**（少了三处要同步的重复口径），
> 但面板顶上留了一行灰字告诉你状态去哪儿看：**"它饿不饿、困不困：右键它，菜单第一行"**。

面板本身还在（右键 →「背包面板」）：金币大字打头 + 小卖部所有商品
（**没买的也画出来**、灰掉、写 ×0）。面板开着时挂了个 1 秒的定时器刷新，关掉就停。

状态条是自绘的（`pet/panel.py` 现在只剩 `BagPanel`）。**没有用 `QProgressBar` + QSS**：
拼出三条带标签的条要 9 个控件，而且"30% 以下转红"这种按数值换色 QSS 做不到，
得在代码里改 `setStyleSheet`，那样每帧都在重新解析样式表 —— 自绘反而更短也更稳。

### 甩出去（拖拽投掷）

拖着它**快速**挥一下再松手，它就会顺着你甩的方向飞出去，撞到屏幕边缘**弹回来**
（每次弹跳损失大部分速度，很快就滚停下）。

- 判定只看**松手那一刻的手速**，不看拖动距离 —— 慢慢拖到墙角再松手，它会静静落地。
- 太慢的挥动不算「甩」（有下限），挥得再猛也不会飞出屏幕（有上限）。
- 关掉「重力下坠」开关时**不甩**（开关优先级高于手速）。

验收：`tools/verify_fling.py` → `reports/fling_throw.png`（4 种松手方式的真实轨迹）。

### 🛒 小卖部：游戏分数换金币，金币换吃的

两个小游戏**结算时**会把分数折成金币（**10 分 = 1 金币**，中途关窗口不给，别想赖账）。
攒下的金币在右键菜单「🛒 小卖部」里花：

| 商品 | 价格 | 效果 |
|---|---|---|
| 肉干 | 12 | 饱食 +35 |
| 玩具球 | 18 | 心情 +35 |
| 豪华大餐 | 30 | 饱食 +50、心情 +20 |

**精力不在货架上** —— 只能靠睡觉补，不然它就成永动机了。
想让它歇会儿不用等它自己累趴下，右键菜单里有**「去睡一会儿」**（v2.4.0 加的，
见前面那一节）—— 但那条路**不多给一滴精力**，只是把这一觉压缩到 1/3 的时间。

> 每天那份免费投喂只够垫一口。想让它一天里吃饱**两次以上**，掏钱买的才是正路 ——
> 细节见下面「喂一口」那一节。

#### 买下来 ≠ 用掉：🎒 背包

v2.1.0 起，**点「买」只是把东西放进背包**（金币扣掉、托盘弹一句"已放进背包"），
**状态一点都不变**。要用的时候去右键菜单「🎒 背包」里点它一下：

```
🎒 背包
  金币 137 · 共 3 件          ← 第一行永远是这两个数
  肉干 ×2        → 使用
  玩具球 ×0      →（灰掉）
  豪华大餐 ×1    → 使用
  用过之后会抬对应的状态
```

- **没买的商品也列出来**（灰掉、写 ×0）—— 这样"还能买什么"一眼看得见，
  而不是"背包里没有就整行消失"，让人以为小卖部缺货。
- `使用` 的顺序是**先从背包扣掉、再抬状态**。反过来的话，会出现
  "状态已经涨了、东西还在背包里"这种白送。
- 数量不够时是**整笔失败**：不会出现"扣到 0 为止"的半吊子状态。
- 为什么要有背包这个中间层：v2.0.0 的「买」是**直接抬状态**的，
  也就是"买了"和"吃了"是同一件事 —— 那样就没有"囤货"这回事，
  也不会有"先买着，饿了再吃"的余地。

#### 「喂一口」每天一次免费，之后吃背包里的

v2.2.1 之前，「喂一口」**完全不看背包**：饱食 +26、冷却 0.35 秒，
从饿到饱只要一秒半、一个金币不花 —— 小卖部于是成了摆设。而饱食偏偏是三条值里
**唯一没有免费回补渠道的**（心情睡觉会回、精力只有睡觉能给），
这条后门一开，"买"这件事就整个失去意义了。

现在菜单那一行**当场算出这一下要花什么**，明明白白写在上面：

```
喂一口（今天免费）                        ← 每天头一次，不看背包
喂一口（吃掉肉干，还剩 1）                 ← 之后的每一次
喂一口（今天的免费用完了，背包里也没吃的）  ← 灰掉，点不动
```

- 那份免费额度是给"一个金币都没有"的时候兜底的，**一天一次**，按本地日期算 ——
  跨天了自动回来，不用任何定时器，每次开菜单现算一遍。
- 之后吃的是背包里**第一样"吃的"**（按商品顺序，所以肉干优先于豪华大餐）。
  玩具球不算吃的：饿的时候啃球没有意义，所以背包里只有玩具时那一行照样灰掉。
- 走的路径和「🎒 背包」里点一下**完全相同**（先从背包扣掉、再加它自己的效果、
  演吃饭的动作），不是另写一遍 —— 于是两个入口永远不会出现"一个扣了、一个没扣"。

### 🍅 番茄钟：陪你专注 1 秒 ~ 2 小时

右键菜单或托盘菜单「🍅 番茄钟」：

- **「自定义时长…」**（主入口）—— 打开一个**三列滚轮**（时 / 分 / 秒），
  用鼠标滚轮、拖拽、`↑↓` 翻格、`←→` 换列都能调，范围 **1 秒 ~ 2 小时**。
  滚一下选中带里的数字就变，上下两行是"前后一格"的预览。
- 一档到底的快捷档位：1 分钟 / 5 分钟 / 25 分钟 / 50 分钟。
- **上次选过的时长记得住**，下次打开对话框就停在那儿。

滚轮有**三条联动规则**（写在 `pet/wheel.py` 里，纯逻辑可单测）：

| 情况 | 规则 |
|---|---|
| 时 = 0 且 分 = 0 | 秒列只能 1..59 —— **滚不到 0**，最短就是 1 秒 |
| 时 < 2 | 分、秒列都是 0..59 |
| 时 = 2 | 分、秒**只剩 0** —— 所以滚到 2 小时会自动把分秒清零，`2:30:50` 这种组合不存在 |

开始后托盘提示还剩多久，**到点时它会蹦一下 + 弹个托盘气泡**（不抢你焦点、不弹窗打断）。

> 为什么番茄钟内部单位是**秒**而不是分钟：分钟表达不了"45 秒"，
> 而 1 秒是这个功能明确要求的区间下限。界面上到分钟为止的显示
> （`25:00` / `1:02:03`）由 `format_clock()` 负责。

### 「重力下坠」这个开关管什么

**勾上（默认）**：松手就往下掉，落到屏幕底会弹一下再站稳；单击会蹦起来。
**不勾**：它不下坠 —— 拖到哪儿松手就**悬在哪儿**，单击也不再往上蹦。
再勾回来就会接着往下掉。

关掉它的时候如果正掉到一半，会就地冻住，而不是硬演完下坠动画
（下坠状态只认"落地"这一个出口，没有重力就永远等不到）。

验收：

```bash
python tools/verify_gravity.py     # -> reports/gravity_switch.png
```

同一只狗、同一个起点，分别跑「勾选 / 不勾 / 中途改」三种设置，各抓一排真帧，
纵轴是真实屏幕高度。实测：勾选下坠 564px、不勾 Δ=0px、中途改掉 110px 后冻住。

「一起玩游戏」是个子菜单，里面有**四个**游戏：弹跳得分 / 接狗狗 / 跑一跑 / 狗粮 2048。

**中途退出不会白丢一局**（v2.5.1）：这一局还没打完时按 `Esc`、点窗口关闭按钮、
或者按 `R` 重开，都会先弹一个确认框，三个出口 ——
**按当前分数结算**（金币和最高分照记，文案写「提前收工」）/
**暂停，回头再玩**（停表藏窗，右键菜单和托盘各多一条「▶ 继续上一局」，
点它接着打）/**取消，继续玩**。程序自己拆窗口（换游戏、退出程序）不弹框，
但暂停那一局会按当时分数结掉并弹托盘气泡，不会被悄悄扔掉。

**弹跳得分**：`← →` 移动，`空格` 或点击画面起跳，`R` 重开，`Esc` 退出。60 秒内敲方块得分，打光全场进入下一轮并加时。

v2.1.0 把它**重做了一遍**（旧版"太无聊"的根源是：每个方块一碰就碎，
于是最优打法就是贴着一个地方反复跳，位置、时机、高度全都不参与决策）：

| 新东西 | 说明 |
|---|---|
| **方块有耐久** | 敲一下扣 1 点，耐久数字画在方块上。**越靠上越硬**（那排离手最远、清台时总是最后剩下），**轮次越高整体越硬**，封顶 6 点 |
| **敲不穿 = 一堵墙** | 球从下面顶到没敲碎的方块 → **被挡回来**；敲碎了 → 方块消失、**球原样继续往上**，于是能连穿上面几排 |
| **踩顶借力** | 从上面踩到没碎的方块会**弹起来** —— 落点踩在方块顶上也有用，不是只能从下面顶 |
| **连击倍率** | 3 连起 ×2、6 连起 ×3。**落地才清零**，所以"能连几下"完全由"这一跳打穿了多远"决定 |
| **掉落道具** | 敲碎一块有 16% 概率掉：「时」+5 秒 / 「力」8 秒内一击必碎 / 「分」8 秒内得分翻倍。接住才生效，掉地上就没了 |
| **轮次递增** | 清台加时从 +5 秒起、每轮 -0.5 秒、下限 +2 秒；总时长有天花板（60 + 45 秒），手气好也不会拖到十分钟 |
| **裂纹看得见** | 敲得越狠颜色越暗、裂纹越多，白闪一下，飘出 `+5 / +10` 的飘字 |

**分数跟着难度一起调过**：现在敲一下 **5 分**（旧版是"碎一块 10 分"）。
因为一块最多要敲 6 下，不调的话同一局的总分翻好几倍，金币立刻通胀 ——
汇率（10 分 = 1 金币）是按"认真打一局够买一两样"定的，得跟着它走。
实测：一局大约 180~540 分 → 18~54 金币，最贵的商品 30 金币，
也就是"认真打一局，够买最贵的那样"。

**接狗狗**：`← →`（或直接用鼠标）移动底下的小黄狗，接住天上掉下来的小白狗加分，躲开炸弹。
**漏掉一只小白狗、或者接到炸弹，各扣 1 滴血；血量上限 5 滴，扣光就 game over。**
存活越久难度越高（掉得更快、出得更密、炸弹更多）；连续接住每满 5 只额外加 10 分。
最高分存在存档的 `best_catch`，和「弹跳得分」的 `best_score` 各记各的，互不覆盖。

v2.0.0 又给它加了两样：

- **骨头（🦴）**：接住 **+10 分**，而且**如果你已经掉过血，额外回 1 滴**（满血时只加分）。
  比炸弹小一圈、出现得比较晚（难度过 30% 之后才可能有），算是个"捡漏"的甜头。
- **风（水平漂移）**：难度过 40% 之后，一部分落体**不再垂直下坠**，会横向飘、
  撞到左右墙**弹回来**。落点不再"站着不动就能接"，得跟着挪。

验收：`tools/verify_catch_items.py` → `reports/catch_items.png`
（真实游戏画面 + 带风落体的 `x(t)` 轨迹与撞墙反弹点 + 骨头占位形象）。
骨头素材包里没有，它是**代码画的占位形象**（风格对齐线条卡通那套）。

**跑一跑**（v2.2.0 新增）：`← →` 加速 / 减速，`空格` 或 `↑` 跳，`↓` 低头，`R` 重开。
横版跑酷：一边往前跑一边躲开三种障碍，**矮墩**跳过去、**高墙**和**垂杆**都得低头钻过。
跑得越远速度越快、障碍越密（按距离分档，最高 780 px/s）。

上手手感靠三件事撑着（少一件就变成"跳不跳得过去全靠运气"）：

| 机制 | 干什么用 |
|---|---|
| **跳跃缓冲**（0.13 秒） | 落地前一刹那按的跳会被记住，落地立刻起跳 —— 不缓冲的话这一下就是**丢输入**，玩家明明按了却没反应 |
| **可变跳跃高度** | 松手就减速上升（`JUMP_CUT=0.42`），所以能"轻点一下跳矮的、按住跳高的" |
| **快速下落** | 按 `↓` 加速下坠，最高点附近不拖沓 |

> 判定盒**对玩家宽容**：玩家的判定盒四周各收 9px / 6px —— "看着擦过去了"就算过；
> 障碍不收，保持"看到什么就是什么"。
>
> **刻意没做土狼时间**（coyote time，跑出平台后还允许零点几秒起跳）。
> 那是给有边缘的平台准备的，这里的赛道是**平的**，没有边缘可走空。

**狗粮 2048**（v2.2.0 新增）：`↑↓←→` 滑，`Z` 撤销（**一局 3 次**），`R` 重开。
把相同数字的格子推到一起合成，**凑出 512 就结算**。

- **一次滑动只合一次**：`2 2 2 2` 右滑出的是 `0 0 4 4`，不会一路合成 `8`。
- **无效方向不冒新块**：顶到墙上时整盘不动，也就没有"可撤销"这一步。
- **撤销退的是棋盘 + 分数 + 次数**（存的是三元组），不是只退棋盘。
- **金币按最大格子算**（512 → 56 金币），不按分数。因为 2048 的分数和"玩得多好"
  脱节（两个 256 合成 512 一次性 +512 分），按分数折算会通胀。
  > 这是本项目**第二把金币尺子**（另一把是 `coins_for` 的"分数 // 10"）。
  > 代价是改汇率要记得两处 —— 两边注释里都写了指向对方。
- 目标进度条是**对数**的（线性的话最后永远卡在 90%，看着像坏了）。

> 四个游戏**空目录也能玩**：素材缺哪套，那套就退回代码画的占位形象（不是成品美术，
> 只是"别让屏幕空着"）。真素材到位后丢进 `assets/game/` 就自动替换，不用改代码 ——
> 命名见 `assets/game/README.md`。
>
> 现在的状态：**素材已到位**。接狗狗用的是「线条小狗」系列真素材
> （小黄狗接板 8 帧、三套不同的小白狗各 10 帧），两个游戏各有一张背景图；
> 只有炸弹还是代码画的（素材包里没有合适的，按线条卡通风格补的）。
> **跑一跑与 2048 的角色/障碍也全部是代码画的**（它们没有现成素材可挑，
> 用线条卡通风格就地画，和桌宠本体一套画风）。

**卡册与抽卡**（v2.3.0 新增）：右键小狗 → 菜单顶上一排**装备徽章**，
下面「卡册」进收集系统。卡册是**翻页网格**，4×3 一页、共 9 页 102 张。

- **抽一次 60 金币**。出率：普通 62% / 稀有 26% / 史诗 10% / 传说 2%。
  抽完会**单独弹出一张大的卡**（v2.6.0）：翻牌入场、光环与粒子按稀有度
  分四档（传说最亮），写「新收集！」或「重复（已有 N 张）」；
  点一下 / 空格 / 回车 / `Esc` 跳过，再点一下收起。
- **未抽到的卡显示成灰色剪影**（保留档位色描边）—— 看得见"还差哪些"，
  但看不清是哪一只。收集进度写在标题旁边：`已收集 34 / 102`。
  收集得差不多之后可以点标题旁的**「仅看已有」**（v2.6.0）只翻自己有的
  那几十张，选择会记住；再点「看全部」切回整本图鉴。
- **重复的卡不会自动变成碎片**。它们在册里叠着（格子角上标 `×3`），
  想分解哪一张由你决定 —— 分解**必须留一张**，不然图鉴就缺一角了。
- **两种碎片**：普通/稀有重复卡拆出**低级碎片**，史诗/传说拆出**高级碎片**。
  低级碎片有两个用途：换普通/稀有卡，或者 **5:1 换高级碎片**（每周上限 34）。
- **兑换每周有额度**（普通 16 / 稀有 5 / 史诗 2 / 传说 1 次），跨周不累积。
  传说卡**只能用高级碎片换**，30 个一次。
- **保底**：同一档连续 3 次兑到重复，下一次必定给没拥有的 —— 传说只有 7 张，
  没有这条规则光靠随机要磨很久。
- **装备加成**：卡册里点一张卡 → 「装备」。5 个槽位**按周解锁**
  （第 1~3 周 1 格，之后每 3 周 +1，第 13 周满 5 格）。
  加成是**金币获取**：普 +1% / 稀 +2% / 史 +3% / 传 +5%，**最高 +20%**。
  装上之后，四个小游戏结算时会多给这一份，结算浮层写「（含装备 +14%）」。

> **单抽价为什么是 60 金币**：装备系统会带来 16~19% 的稳定收入加成，
> 把价格定在 60 **正好抵消它**。换句话说，装备不是"加速器"而是"回到原点" ——
> 一件都不装要 31 周集齐，装满 5 格才回到 26 周（约半年）。收藏因此才有分量。
>
> 完整推导（出率、兑换价、额度、保底、梯度）在 **[`docs/抽卡参数方案.md`](docs/抽卡参数方案.md)**
> 的 v1.1 定稿里 —— 那套数字是蒙特卡洛模拟出来的，不是拍脑袋定的。

**重要**：无边框窗口没有关闭按钮，退出只能从右键菜单或托盘菜单走。调试期间如果卡住了，用任务管理器结束 `python.exe` / `pythonw.exe`。

### 幼儿模式：把桌面锁起来，只留桌宠给小朋友玩（v2.5.0）

给小朋友玩电脑用的：开了之后**只有桌宠能点**，桌面上的其他东西碰不到。
入口是**右键桌宠 →「幼儿模式」**（刻意不放托盘：托盘就在任务栏上，
而任务栏正是这个模式要挡住的地方）。

| | 鼠标点图标 / 任务栏 | Win / Alt+Tab / Alt+F4 | 代价 |
|---|---|---|---|
| **安全档** | 完全挡住 | 拦不住 | 无。纯窗口层次，不碰系统 API |
| **严格档** | 完全挡住 | 也挡住 | 装了低级键盘钩子，**杀软可能报毒**；钩子出问题会让键盘顿一下 |

**退出**：按住屏幕**右上角**约 1.5 秒 → 弹出小键盘 → 输 4 位密码。
（为什么藏在右上角：小朋友按不出"按住某个角落 1.5 秒"这种操作。）

它到底靠什么锁住、两档具体差在哪、真机怎么验收，都写在
**[`docs/幼儿模式.md`](docs/幼儿模式.md)**。这里只列四条你该知道的事：

1. **重启即解除，绝不写进存档**。`config.json` 里只有那个密码，没有任何
   "正在锁定"的字段 —— 否则程序被任务管理器杀掉之后重启会自己锁上，
   那就真成"电脑坏了"了。
2. **没设密码不许进**，所以不存在"进去了退不出来"。
3. **密码是明文存的**。忘了就打开 `config.json` 看 `kids_passcode`，
   或者把它改成 `""`，下次会重新让你设一个。这是个**家长给自己用的锁**，
   唯一的失败模式是家长把自己锁在外面，所以后路留得很宽。
4. **卡住了就按 `Ctrl+Alt+Del`**。它是 Windows 的安全注意序列，
   任何钩子都拦不住 —— 用它开任务管理器结束程序即可。

> 别以为它万能：安全档挡不住系统级键盘手势；任务栏是靠遮罩"盖住"而不是
> "藏起来"，极端情况下理论上可能露一下可点的空档。要锁得更死就选严格档。

## 素材放在哪：一张决策表

这是最容易搞混的地方 —— 几个目录长得像，用途完全不同：

| 目录 | 性质 | 程序优先级 | 用来放什么 |
|---|---|---|---|
| `custom_pet/` | 用户数据，**可写** | **最高**（有 `*.png` 就整体接管 `assets/pet/`） | 你自己换的形象；**当前现役素材在此** |
| `assets/pet/` | 程序内置，**只读** | 低（被 `custom_pet/` 接管后就不读） | 随程序分发的内置贴图 |
| `assets/game/` 或 `%APPDATA%\DesktopPet\game\` | 同上规则 | 同上（按 `assets/game/` ← 用户目录） | 小游戏素材 |
| `assets/raw/inbox/` | 素材投递口 | —— | **下载来的 GIF 先丢这里**，再跑 `intake.py` |
| `assets/raw/_library/` | 素材库归档 | —— | 整批下载原样留档，**不参与加工** |
| `assets/raw/_archive/` | 加工完的原始输入 | —— | 入库后原文件挪到这里（⚠️ 你的原稿，别整个删） |
| `assets/raw/_snapshots/` | 历史成品快照 | —— | 原图丢了时重摆用 |

> 打包后 `custom_pet/` 与用户 `game/` 挪到 `%APPDATA%\DesktopPet\`（程序目录通常不可写）。
> 这套"资源目录（只读）/ 数据目录（可写）"的规则实现在 `pet/paths.py`，**加一类素材只用在
> `ASSET_KINDS` 里登记一行**，三个路径函数就都认它了。

不确定的时候用 `--custom` 走用户目录，它不会污染项目文件：

```bash
python tools/prep_sticker.py assets/raw/我的表情.gif --state idle --auto-key --custom
```

## 换成你自己的素材

内置贴图是代码画出来的（两套风格都不依赖任何外部素材）。要换成自己的宠物，有四条路。

### 路线一：批量投递（推荐，不用分类也不用改名）

**把下载到的所有东西全丢进 `assets/raw/inbox/`**，然后：

```bash
python tools/intake.py            # 只看方案：每个文件被判成什么、准备放哪儿、依据是什么
python tools/intake.py --apply    # 确认无误后落位
```

`intake.py` 负责四件事：

1. **认类型** —— 图片 / 音频 / 字体 / 视频，各有各的去处。视频和 PSD 会被明确拒绝并告诉你为什么。
2. **认动作** —— 图片先看文件名里的关键词（`发呆`→idle、`跑`→walk、`被拎`→drag、`掉落`→fall、`逗他玩`→poke、`喂一口`→feed）；
   名字看不出来就看**动图的运动轨迹**：横向位移占优 = 走路，纵向往返 = 原地起跳式的互动反应，
   抬上去不回位 = 被拎起来，一路往下 = 下落。
3. **归位** —— 白底自动抠图、整组统一缩放、按 `<状态>_<序号>.png` 落进 `custom_pet/`。
4. **顺手换图标** —— 有宠物素材入库就重裁一遍 `assets/icon.png` / `icon.ico`。
   不然会出现"桌面上的狗换了、托盘上还是上一只"。不想动图标加 `--no-icon`。

自动判定不准就用 `--map` 当场指定，不用改名：

```bash
python tools/intake.py --map 晃脚=idle --map 害怕=drag --apply
python tools/intake.py --zoom 晃脚=1.15 --apply     # 某套单独放大 15%
python tools/intake.py --scale 逗他玩=0.56 --apply   # 直接钉死某套的缩放比（见下）
python tools/intake.py --as idle --apply            # 全部当待机
python tools/intake.py --dir D:/下载/狗勾表情包 --apply   # 换个扫描目录
python tools/intake.py --builtin --apply            # 直接写 assets/pet，覆盖内置
python tools/intake.py --motion keep --apply        # 保留素材自带的弹跳
python tools/intake.py --face left --apply          # 声明这批素材原图朝左（见下）
```

几个设计上的取舍：

- **默认不动手**，先打印方案。落位要你明确加 `--apply`。
- **默认写 `custom_pet/`** 而不是 `assets/pet/` —— 不覆盖内置素材，想恢复删掉 png 就行。
- **一个动作匹配到多个文件会警告**。不同角色的素材拼进同一套动作，播放时会"变脸"。
- **跨素材共用一个缩放比**（取各套"刚好放进画布"的最小值）。同一只角色的几套表情包，
  狗在原始素材里本来就一样大；如果各套各自"缩放到填满画布"，带道具的那套
  （比如狗坐在长凳上）并集更大、被缩得更小，一拖起来角色就"长大"了。
  实测：某套素材单独能到 0.784，而全局取 0.678，所以每套都留了余量；嫌小用 `--zoom` 调。
- **分两次投递的素材要自己对齐尺寸**。缩放比是"本批投递的几套"里取的，隔几天再入
  一套，两批尺寸不会自动一致。做法：量两套素材里角色头部的像素宽度，用 `--zoom`
  把新那套对齐到旧的。**量的时候按角色身体颜色量**，别用整体包围盒 —— 装饰性的
  虚线、道具、画面里第二只角色都会混进去，量出来看着一致、其实是装饰的宽度。
- **`--motion` 决定素材自带的位移怎么处理**。默认 `flatten`：每帧的脚都落在同一条
  地平线上，位移完全交给窗口。这对"原地做动作"的素材是对的（坐在凳子上晃脚），
  但**自带弹跳的素材会被压成"脚踩地原地伸缩"**，腾空感全丢。这类素材用
  `--motion keep`：所有帧共用一个坐标系，水平居中、垂直位移原样保留。
- **`--face` 决定"素材原图朝哪边"**，写错的表现就是**狗倒着走**（详见下一节）。
- 原文件执行后挪进 `assets/raw/_archive/<时间戳>/`，不会重复处理，也能随时翻回去。

### 同一个动作放多套素材：每次随机演一套

一个动作可以有**好几套**素材，每次触发（左键单击、右键「喂一口」）随机挑一套播，
让同一只狗显得更有反应。**不用改代码，放素材就生效**：

```
custom_pet/
├── poke_00.png  poke_01.png …      ← 不写套名 = 默认那一套（老素材照旧）
├── poke_a_00.png  poke_a_01.png …  ← 套 a
└── poke_b_00.png  poke_b_01.png …  ← 套 b
```

命名规则只有一条：**`<状态>_<套名>_<序号>.png`，套名用字母**
（写成数字会被当成序号，比如 `poke_01` 是默认套的第 1 帧）。
加工时把套名一起写进 `--state` 就行：

```bash
$PY tools/prep_sticker.py 开心摇摆.gif --state poke_a --custom --scale 0.42
```

当前已经分套的：**逗它玩 3 套、喂一口 3 套、走路 2 套**。

三个设计细节：

- **几套帧数不一样也没关系** —— 动作时长按**这次挑中的那一套**算（帧数 ÷ 帧率），
  短的那套不会被掐断，长的那套也不会播完还空转。
- **连续两次不会挑到同一套**（挑的时候排除上次用过的那套），所以两套素材就是完美轮换，
  不会出现"怎么点了没变"。
- **只有一套时不假装随机**；`drag` 现在是单套，但按同样规则放一套 `drag_a_*` 进去，
  它也会自动开始随机。

循环状态要单独说 —— 它们都是"停得住"的状态，处理却相反：

| | `idle` | `walk` |
|---|---|---|
| 参与轮换 | 不参与，固定用默认套 | 参与 |
| 什么时候挑 | —— | **起步那一刻**挑一套，整段行走不换 |
| 为什么 | 要停好几秒，中途换套画面会跳 | 只换在起步那一帧，看不到接缝；两套帧数不同（8 / 14），中途换会接不上 |

walk 没有任何"点一下"的入口可以挂钩，只能在主循环里比对状态
（`PetWindow._track_state`）。**区分点是"换套的那一帧会不会被看见"，不是"是不是循环状态"。**

验收：

- `python tools/verify_variants.py` → `reports/variants.png`：连点若干次，
  把**每次真正画出来的那一帧**拼成对照图，一眼看出几套有没有轮着上。
- `python tools/verify_walk_sets.py` → `reports/walk_sets.png`：反复让它起步 6 次，
  每格标出这次用的套名（交替生效就会看到 `a / 默认 / a / 默认 …`）。

### 路线二：直接替换（素材已经抠好透明底）

把 128×128 的透明 PNG 按下面的命名丢进 `custom_pet/`（推荐）或 `assets/pet/`。
**同一动作可以放多套** —— 文件名里加一段字母套名即可，程序每次触发会随机挑一套：

```
<状态>_<序号>.png            idle_0.png   idle_1.png   …        待机
<状态>_<套名>_<序号>.png      poke_a_0.png poke_b_0.png …        逗它玩（每次随机演一套）
```

状态名（= 贴图前缀）只有六个，定义在 `pet/behavior.py` 的 `State`：

```
idle  待机      walk  行走      drag  被拎起
fall  下落      poke  逗它玩    feed  喂一口
```

某个状态一个文件都没有时，程序会自动借 `idle` 的帧顶替，不会崩，只是动作会不对。
更细的规则见 `assets/pet/README.md`。

### 别让狗倒着走：贴图朝向

程序只知道"往哪走"，不知道"素材画的是哪一边"。这两件事一旦对不上，狗就会
**背对着前进方向滑走** —— 而且代码上看不出任何毛病，只有眼睛能发现。

所以把"原图朝哪边"当成素材自带的属性，和贴图放在同一个目录里：

```jsonc
// custom_pet/facing.json
{
  "base": "left",                    // 整个目录的默认：素材原图朝左，向右走时自动水平镜像
  "sets": { "walk_a": "right" }      // 例外：这套原图朝右，单独覆盖
}
```

绘制时只在**行走方向 ≠ 素材朝向**时才翻转。改法：

```bash
python tools/set_facing.py                     # 看当前声明，以及各套左右走各自要不要镜像
python tools/set_facing.py flip                # 在当前声明上直接翻过来
python tools/set_facing.py flip --set walk_a   # 只翻某一套
python tools/intake.py --face left             # 入库时顺手声明（这批素材原图朝左）
```

一个动作可以有好几套素材，而各套是分开抠的图，**原图方向未必一致**，所以朝向
要能按套覆盖。`sets` 的 key 是**素材前缀**（`walk_a`，跟 `walk_a_00.png` 对得上），
不是裸套名 —— 裸的 `a` 在 `walk_a` / `poke_a` / `feed_a` 里重名，一定会互相串台。

不想敲命令就右键桌宠 → `左右翻向（走反了改这个）`，立刻生效，并且写回 `facing.json`
（按套的表也跟着一起翻，否则相对关系就被翻没了），下次启动保持。

**怎么判断该填哪边**：看素材里**头在哪一侧**。当前这套「线条小狗」脸在左边、
后腿在右下方，所以是朝左（`base=left`）；`walk_a` 是唯一例外（前爪朝右举起、
小尾巴甩在左下）。判断完别只信自己的眼睛，跑一遍验收：

```bash
python tools/verify_facing.py     # 出 reports/facing_fix.png，逐套打印像素比对
```

它会真的 `new` 一个窗口，**对每一套素材**分别渲染"向右走"和"向左走"，再拿这两帧
跟该套的原图/镜像各比一次像素差，只有"向右走 ≈ 镜像、向左走 ≈ 原图"才算通过
（实测默认套 向右走 原图差 28.2 / 镜像差 1.06、向左走 原图差 0.01；`walk_a` 向右走
原图差 0.01、向左走镜像差 2.81 —— 都差两个数量级）。**这个验收是必须跑的**：
朝向从代码上看不出对错，只有像素数字能证明。

### 路线三：单个文件手工预处理

用法见 `assets/raw/README.md`。**GIF 动图走这条**（`intake.py` 底层用的就是它）：

微信表情包通常是「白底、不带透明通道、只有一个动作」。直接拿来用会有两个问题：桌面上出现一个白色方块，以及动作凑不齐。预处理工具就是解决这个的：

```bash
# 白底 GIF -> 待机动作（自动探测底色并抠掉）
python tools/prep_sticker.py 我的表情.gif --state idle --auto-key

# 一张 4x4 精灵表 -> 行走动作
python tools/prep_sticker.py sheet.png --sheet --cols 4 --rows 4 --state walk

# 手动指定底色，容差调大一点处理边缘毛边
python tools/prep_sticker.py 表情.gif --state idle --key-color "#FFFFFF" --tolerance 40

# 输出到用户数据目录，覆盖内置贴图（不污染项目文件）
python tools/prep_sticker.py 表情.gif --state idle --auto-key --custom

# 小游戏素材 / 背景图走同一套思路，但目标是 assets/game/
python tools/prep_sticker.py 小黄狗.gif --state catcher --game --size 160
python tools/prep_bg.py 大图.png --name bg_catch --ground 0.78 --preview
```

工具默认按「脚底对齐」把每帧贴到画布底部，这样不同高度的帧凑成走路动画时不会上下乱飘。
整组帧共用**同一个缩放比**（先用所有帧的并集包围盒算一次），不是逐帧各自缩放到填满画布 ——
后者会把"呼吸""张手"这类尺寸变化抹平，播放时角色像硬纸板一样纹丝不动。

**动作不够怎么办**：一个表情包只有一种动作，硬凑是凑不齐的。推荐只留一个表情做 idle，其余动作靠代码补——位移 + 左右镜像 + 上下浮动就是行走，旋转抖动就是被拎，垂直拉伸就是下落。项目早期那套自绘生成器就是按这个思路做的：只有一套身体几何，却生成了 22 帧动作（生成器已删，思路仍成立）。

### 路线四：换图标（托盘 / 窗口 / 任务栏）

图标和贴图是**两回事**：贴图是桌面上那只狗，图标是托盘、小游戏窗口标题栏、任务栏按钮上那个小头像。换完贴图图标不会自动变，得单独说一声：

```bash
python tools/make_icon.py              # 从当前素材裁出头部，更新 icon.png + icon.ico
python tools/make_icon.py --preview    # 顺便出一张各尺寸对照图 reports/icon_preview.png
python tools/make_icon.py --head 0.40  # 头部比例调小（默认 0.46）
python tools/make_icon.py --dry-run    # 只看会裁哪一块，不写文件
```

规则只有一条：**图标跟随贴图**。贴图从哪来（`custom_pet/` 优先，否则 `assets/pet/`），图标就从哪裁，
所以不会出现"换了宠物、图标还是上一只"。`tools/intake.py` 入库后会顺手同步它
（程序启动时也会在图标缺失时补一个，**只补不覆盖**）。

两个细节：

- **只裁头部**。整只狗缩到托盘那个 16px 里只剩一团糊。裁剪框是按"内容包围盒的上 46%"自动算的，
  不是写死的像素，所以换一套素材也不用改代码。
- **输出 `.ico` 而不是只有 `.png`**。Windows 的托盘要 16、任务栏要 32、Alt-Tab 要 64，
  一个包里塞了 7 档，系统按场景自己挑，比自己缩一张 256 清晰。程序优先加载 `.ico`。

想用自己的图（而不是从宠物素材裁）？把 PNG 丢进 `assets/raw/inbox/`，文件名里带 `icon` 或 `图标`，
入库时会直接采用，并自动补出 `.ico`。

   v2.1.0 那套 HUD 登记表时，`HUD_WIDEST_PX`（每段最宽内容的像素宽）是照着弹跳得分
   的经验**估**出来的，结果三处都偏小：`tier 52/57`、`speed 62/65`、`tile 62/71`，
   2048 的 `tile` 与 `undo` 两段**差 1px 就叠上了**。要命的是**冒烟测试用的就是登记值** ——
   登记值偏小，断言反而查不出真重叠。这是同一个病（叠字）第二次犯，教训升级为：
   - 登记值必须是**在真实平台上量出来的**（`tools/verify_v22_ui.py` 跑完会把
     "登记值 / 实量"并排打印，超了就标 `<- 超了！`），估计值没有意义；
   - 断言从"墨迹不叠"升级成"**分配出去的槽位本身就不叠**" —— 墨迹不叠会被
     "某段恰好比最宽内容还短"骗过去，槽位不叠不会。
11. **加新系统时要回头数一遍"老入口"有没有绕过它**（v2.2.1 才补上）。v2.1.0 上了
   背包和小卖部，把「买」改成了"先入库、要用再点"—— 但菜单顶上那个「喂一口」没跟着动，
   它**根本不认识背包**：饱食 +26、冷却 0.35 秒，从饿到饱只要一秒半、一个金币不花。
   于是小卖部成了摆设，这条后门一留就是两个版本。
   要命的是**两轮验收都没发现**：测试全绿、图也好看 —— 因为它不是"坏了"，
   是**两条路给同一个数**，没有任何断言会因为"白送也能涨"而失败。
   - 教训一：新加的资源系统（背包 / 金币 / 商店）必须**数一遍所有会改那个数值的入口**。
     当时饱食的入口有三个（喂一口 / 肉干 / 豪华大餐），只改了后两个。
   - 教训二：**该不该留免费兜底，要看那个数值有没有别的回补渠道**。心情睡觉会回、
     精力只能睡觉给，三条值里只有饱食除了吃没有来源 —— 所以"免费喂一口"等于把
     唯一的稀缺资源做成了无限供应。

这几条现在都写进了对应函数的注释里 —— 都属于"改动看起来无害、结果却错"的类型。

## 打包成 exe

```bash
pip install pyinstaller
pyinstaller --noconsole --onefile --name DesktopPet ^
  --add-data "assets;assets" ^
  main.py
```

三个坑：

1. **素材路径**。`config.app_root()` 已经处理了冻结态（读 `sys._MEIPASS`），所以不用改代码；但如果你自己新加了按相对路径读文件的地方，记得走同一个函数。
2. **存档位置**。冻结态下配置写到 `%APPDATA%\DesktopPet\`，因为程序目录通常不可写。
3. **杀软误报**。PyInstaller 单文件包被 Windows Defender 拦是常态，给同学之前先说明。
4. **体积**。PySide6 打进来约 60–100 MB，这是 Qt 的硬成本，压不下去。

## 已知限制

- 只支持 Windows。macOS 的透明窗口和托盘 API 不同，需要另写适配层。
- 高 DPI 下已设 `PassThrough` 取整策略，多显示器之间拖动正常；但如果某个显示器缩放比例很怪，仍可能出现一次坐标跳变。
- 置顶窗口会盖住全屏游戏和 PPT 演示。目前只能从托盘菜单临时隐藏，没有做自动侦测。
- 远程桌面或老显卡驱动下，透明窗口可能出现黑边。
- **「逗它玩」素材里的花会被窗口边缘裁掉几片**：动作窗口就是 128×128，而素材里花开得
  比画布还大（并集 313px，缩到狗的尺寸后仍有 175px）。缩放比按**狗的尺寸**定
  （0.56，和其它动作对齐），花就只能超出画布——要完整显示得给动作临时放大窗口，
  为一段 0.5 秒的动画不值当。狗本身、以及脚下的位置都是准的。
- **睡觉那套比别的动作矮一截**（v2.0.0）：`sleep` 是趴卧的横长姿势（112×62），
  而其余状态内容高 94~109。它的缩放比是按"刚好放进画布"**自动算**的，
  宽边成了限制维度，所以高度只有 62 —— 这是睡姿本身的形状，不是缩放错了。
  好在它躺着，视觉上不违和；真要统一高度，得手工用一个更小的 `--scale` 再落一次。
- **养成数值改完要连文件一起看**：`pet/vitals.py` 顶部的常量是唯一来源，
  但 `TIRED_AT`（进睡眠）**必须低于** `RESTED_AT`（出睡眠），
  写成一样会每帧睡醒横跳（这个坑 v2.0.0 真踩过，见 `CHANGELOG.md`）。

## 架构上的三点说明

**物理与素材是共享的。** 桌面上的宠物和小游戏里的球，用的是同一个 `pet.physics.Motion` 和同一套贴图。多写一份碰撞代码不难，难的是半年后你改了一处忘了另一处。

**行为收敛成状态机，而不是一堆 if-else。** 每个状态对应一套帧序列和一个明确的转移条件，加新动作（比如睡觉）只需要往 `behavior.py` 的 `State` 枚举里加一条，窗口、素材、命令行白名单会自动跟着认（见下）。

**登记表消灭了重复清单。** 项目里凡是"一份清单被好几处抄写"的地方，都收成了单一来源：

| 单一来源 | 管什么 | 加东西的成本 |
|---|---|---|
| `pet/behavior.py` 的 `State` | 动作名 / 贴图前缀（`assets.STATES`、`prep_sticker.VALID_STATES` 都从它派生） | 加一个枚举成员 |
| `pet/paths.py` 的 `ASSET_KINDS` | 素材类别与"内置 / 用户"两套目录 | 加一行 `AssetKind(...)` |
| `pet/menu.py` 的 `TOGGLES` | 右键菜单与托盘菜单里的开关项 | 加一行 `Toggle(...)` |
| `pet/menu.py` 的 `SHOP`（v2.0.0） | 小卖部商品：名称 / 价格 / 效果（右键菜单、托盘菜单、背包、状态面板共用） | 加一行 `ShopItem(...)` |
| `pet/menu.py` 的 `POMODORO_CHOICES`（v2.1.0 起单位是**秒**） | 番茄钟快捷档位 | 加一个数 |
| `pet/wheel.py` 的 `COLUMNS` / `FULL_CYCLE`（v2.1.0） | 滚轮的三列与每列一圈多少格 | 改一行 |
| `pet/wheel.py` 的 `WheelModel._settle`（v2.1.0） | 时/分/秒的联动规则（2 小时上限、1 秒下限） | 改这一段 |
| `pet/vitals.py` 的常量（v2.0.0） | 养成数值：衰减率 / 各项阈值 / 商品生效值 | 改一个常量 |
| `game/common.py` 的 `COIN_PER_SCORE`（v2.0.0） | 分数→金币折算率（bounce / catch / runner 共用；**2048 例外**，见下一行） | 改一个常量 |
| `game/minigame.py` 的 `DROPS`（v2.1.0） | 掉落道具清单（同时要加 `_take_drop` 的一个分支） | 加一行 `PowerUp(...)` |
| `game/minigame.py` 的 `HUD_ZONES` / `HUD_FONT` / `HUD_WIDEST_PX`（v2.1.0） | 顶部信息条五段文字的位置、字号、最宽像素 —— **改 HUD 文案要连 `HUD_WIDEST` 一起改** | 改表里的数 |
| `game/common.py` 的 `zone_spans` / `overlapping_zones`（v2.2.0） | 三款游戏共用的 HUD 排版算术（槽位换算成区间、查重叠） | 一个游戏都不用改 |
| `game/runner.py` 的 `KINDS`（v2.2.0） | 三种障碍的尺寸与"是不是半空吊着" | 加一行 `Kind(...)` |
| `game/runner.py` 的 `PATTERNS`（v2.2.0） | 障碍组合，每项是 `(种类, 相对 x)` 的若干组 | 加一组 |
| `game/runner.py` 的 `GAP_SEC_START` / `SPEED_STEP` / `MAX_SPEED`（v2.2.0） | 跑一跑的难度曲线：起步速度、每档加速、封顶 | 改常量 |
| `game/g2048.py` 的 `TARGET`（v2.2.0） | 目标格子（凑出来就结算） | 改一个数 |
| `game/g2048.py` 的 `TILE_COLORS` / `TILE_FONT`（v2.2.0） | 各数字格子的配色与字号 | 改表 |
| `game/g2048.py` 的 `coins_for_tile`（v2.2.0） | 2048 专属的金币尺子（按最大格子） | 改这一处，**另一把尺子在 `game/common.py`** |

以前这几处都是各抄一份，加东西时要记着改两三个文件，**漏掉的那次不报错**，只表现为"放进去的东西程序不认"或"菜单里少一项"，最难查。

## 怎么扩展

### 加一个动作

照着 `poke` 抄一遍，**只需要动两个文件**：

1. `pet/behavior.py` —— `State` 里加一个成员（成员值就是贴图前缀，两者天然同名）；
   `FPS` 字典里补一行帧率。要它"播完自动回 IDLE"，把它加进 `ONESHOT` 元组。
2. 挂到交互上 —— `pet/window.py` 加个方法（一次性动作记得传 `_oneshot_seconds()` 算时长），
   菜单项走 `pet/menu.py` 的 `add_interactions`。

**不需要再改** `assets.STATES` / `prep_sticker.VALID_STATES` —— 它们都从 `State` 派生。
加完跑一次 `tools/smoke_test.py` 和 `tools/typecheck.py`。

### 给已有动作加一套素材（换着演）

**不用改任何代码**：在素材目录里按 `<状态>_<套名>_<序号>.png` 放一组新图就行
（套名用字母，例如 `poke_c_00.png`）。程序每次触发会随机挑一套，并排除上次用过的那套。

```bash
python tools/prep_sticker.py 我的新素材.gif --state poke_c --custom
```

`idle` 不参与随机（它在状态里停好几秒，中途换套画面会跳）；`walk` 只在**起步那一帧**换套，
整段行走保持一致。

### 卡册：加一张卡 / 调数值

**加一张卡**（换一整套素材同理）：

1. 把 PNG 放进素材目录，在 `docs/卡片分档.csv` 里加一行。
   **`idx` 只能往后排、不许插队** —— 卡的 id 就是 `c<idx>`，插队会让所有人
   存档里已有的卡全部对不上号。
2. `python tools/build_cards.py` 重新生成 `cards.json` 与缩略图。
3. 完事 —— 页数、格子、未收集剪影、徽章全都是自动的。

**调数值**（出率 / 单抽价 / 兑换价 / 周额度 / 加成）：参数集中在
`pet/cards.py` 文件头上那一块，每条都写了它牵动什么。改完必须做两件事：

```bash
python tools/check_cards.py     # 规则有没有被改坏（51 项）
python tools/verify_album_ui.py # 界面还画得出来吗（24 项）
```

以及**回去读一遍 `docs/抽卡参数方案.md`** —— 那套数字是模拟出来的，
而且**互相联动**：单抽价、每局产出、兑换价、周额度、保底，动一个会牵动另外几个
（最典型的一条：只改单抽价、不动每局产出，等于把整条时间线整体拉长）。
方案文档里留着每次扫描的对照表，改之前先看那一节。

### 加一个开关（自动漫步 / 重力下坠 / 始终置顶 之类）

1. `pet/config.py` 的 `Config` 里加一个字段（**必须有默认值**，否则老存档读不进来）。
2. `pet/window.py` 里写一个 `set_xxx(bool)` 方法，改字段 + 生效。
3. `pet/menu.py` 的 `TOGGLES` 加一行 `Toggle("字段名", "菜单标签", "setter 方法名")`。

右键菜单和托盘菜单**都会自动多出这项**，勾选状态也自动同步。

### 加一样小卖部商品 / 加一档番茄钟时长 / 加一种掉落道具

前两处都只加一行（`pet/menu.py`）：

```python
# 小卖部：加一样商品 —— 右键菜单、托盘菜单、背包、状态面板同时生效
ShopItem("cake", "小蛋糕", 22, "feed", (("satiety", 20.0), ("mood", 20.0)))

# 番茄钟：加一档时长（数字，**单位是秒**）
POMODORO_CHOICES = (60, 300, 1500, 3000, 2700)
```

`ShopItem` 的第 4 个参数是**用掉时演哪个动作**（要能在 `State` 里找到），
第 5 个是**给哪些数值加多少**（键取自 `vitals.FIELDS`）。
**注意**：精力 `energy` 故意不在任何商品的效果里 —— 只有睡觉能补。

番茄钟档位的单位是**秒**：写法是 `1500`（25 分钟），不是 `25`。
写成 `25` 会被当成 25 秒 —— 这是从 v2.0.0 的"分钟"改过来时最容易踩的一脚。
`tools/smoke_test.py` 里有一条专门盯着这个清单的单位。

掉落道具在 `game/minigame.py`，也是两处：

```python
# 1) 登记表里加一行（label 只有一个字 —— 32px 的方块里放不下两个）
DROPS = (... , PowerUp("freeze", "冻", "冻结方块", QColor(140, 200, 235), 0.20))

# 2) _take_drop 里加一个分支，写清它干什么
elif kind == "freeze":
    ...
```

**别做"改动物理手感"的道具**（减速、变大之类）：它会让跳跃高度跟着变，
"够不够得到上面那排"就变成一个随时在变的量，玩家学不会 —— 这是刻意的取舍。

### 调养成手感（饿得快不快、什么时候睡）

全在 `pet/vitals.py` 顶部的常量里，**改一处全局生效**（衰减、阈值、商品增益、离线规则
都在这个文件，没有第二份）：

```python
SATIETY_PER_MIN = 0.21     # 饱食衰减 /分钟（调大饿得快）
ENERGY_PER_MIN  = 0.28     # 精力衰减 /分钟（调大困得快）
HUNGRY_AT       = 30.0     # 低于它 -> 自己走向屏幕中间讨饭
TIRED_AT        = 25.0     # 低于它 -> 趴下睡
RESTED_AT       = 82.0     # 睡到高于它才醒（**必须高于 TIRED_AT**，否则会反复睡醒抖动）
OFFLINE_FLOOR   = 30.0     # 离线回来时的下限（保证饿不死）
```

> **`TIRED_AT` 与 `RESTED_AT` 之间就是"滞回区"**：进睡眠用低的那个、出睡眠用高的那个。
> 把它俩写成同一个值，宠物会每一帧都在"睡 / 醒"之间横跳 —— 这个坑在 v2.0.0 真踩过
> （36 小时抖了 1052 次），改完降到 10 来次。改这两个数时别手滑。

### 加一类素材（音效 / 字体 / 以后的新类别）

`pet/paths.py` 的 `ASSET_KINDS` 加一行：

```python
AssetKind("voice", "语音", user_dir="voice"),   # 内置 assets/voice/，用户 %APPDATA%/DesktopPet/voice/
```

`asset_dir("voice")` / `user_asset_dir("voice")` / `resolve_asset_dir("voice")` 立刻都能用，
"用户目录有文件就整体接管"的规则也自动生效。`user_dir=""` 表示这类素材没有用户覆盖层。

### 加一个游戏

1. `game/` 下新增一个模块，窗口继承 `game.common.GameWindow`，
   实现两个必填钩子 `_step(dt)` / `_reset_scene(first)`（覆盖钩子**参数名要和底座一致**）。
2. `game/__init__.py` 的 `GAMES` 清单里加一项，`create_game()` 里加一个 `if`。

托盘菜单和桌宠右键菜单**都遍历 `GAMES`**，所以两处菜单自动就有了。
小游戏素材的命名前缀靠扫目录得出（`catcher.discover_puppy_prefixes`），加第 5 套小白狗也不用改代码。
> v2.2.0 的「跑一跑」和「狗粮 2048」就是照这两步加的，**总共只动了 `game/__init__.py` 两处**
> （`GAMES` 加两行、`create_game()` 加两个分支），菜单一行没碰 —— 这套扩展方式实测好用。

**四款游戏窗口共用一个底座 `game.common.GameWindow`。** 窗口尺寸与标题、强焦点策略、16ms 精确计时器、结算浮层的建/居中/显示、**中途退出的确认框与暂停-恢复**、关闭时把本局得分发出去 —— 这些游戏之间必须一模一样，抄几份迟早会漂。底座上：

- `closed = Signal(int)` 声明在**这里**（一局结束带着本局得分发出来，`main.py` 靠它解除桌宠的暂停）。以前这行分别写在两个游戏里、外加一句注释说"记得保持签名一致"，而 `main.py` 手里的窗口变量标成 `QWidget`，类型检查器就报"QWidget 没有 closed 属性"——**这份契约本来就该有个地方写下来**。
- 子类只实现两个必填钩子 `_step(dt)`（一局进行中怎么动）和 `_reset_scene(first=False)`（回到开局），
  再按需覆盖 `_countdown` / `_settle` / `_decay` 三处：计分制在 `_countdown` 里扣时间、
  血量制不覆盖就行。

具体加一个动作的步骤见上一节「怎么扩展 → 加一个动作」。
