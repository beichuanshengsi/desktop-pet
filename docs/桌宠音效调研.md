# 桌宠音效调研 · 别人的桌宠到底用什么

> 起因：v2.9.0 做音效时你说"**去 GitHub 这些开源平台找一下别人的桌宠一般用什么音效素材**"。  
> 下面是查证结果。**查证时间 2026-10-15**，看的是当时的 README / 仓库结构 / 发布说明。

---

## 一、结论（先看这个）

**1. 不存在"桌宠专用音效包"这种东西。** 搜遍了没有。原因不难想：桌宠千差万别  
（狗、猫、动漫角色、Bongo Cat），需要的动作也各不相同，做不出通用的一个包。

**2. 最流行的桌宠 Shimeji，原版根本不带音效。** 市面上下载到的"XX shimeji 桌宠"  
都带声音，但那些是**改版塞进去的角色语音包**（下一节细说），不是音效系统。

**3. 社区通用做法就两条路：**

- **要"动作音"** → 直接拿 **CC0 游戏音效包**（Kenney / Juhani Junkala / Freesound）；
- **要"角色声"** → 自己配**语音包**（`phrases.json` 一类）。

**4. 我们走的是第一条路，而且和最有参考价值的一个开源桌宠（Bongo Cat）几乎撞方案**  
—— 同一个播放后端（pygame）、同一套素材规范（短、归一化）。见第四节。

---

## 二、看过哪些项目

| 项目                                           | 音效方案                  | 播放后端         | 素材来源                                 | 授权  |
| -------------------------------------------- | --------------------- | ------------ | ------------------------------------ | --- |
| **Shimeji-ee**（Group Finity，最流行的桌宠本体）        | **无音效**               | —            | —                                    | 开源  |
| **luinbytes/bongocat**（Bongo Cat，Python）     | 5 个固定槽位，可自定义          | **pygame**   | 自带 + `generate_sounds.py` 合成         | 开源  |
| **jason131415/xiaohei-desktop-pet**（小黑猫）     | 10 个：8 猫叫 + 落地 + 扑击   | **winsound** | **Mixkit 真实猫叫** + `soundsynth.py` 合成 | MIT |
| **panzhaohu666/desktop-pet**（桌宠精灵）           | 每套皮肤 12 条语音           | —            | `phrases.json` 语音包                   | —   |
| **zhouminjian/desktopet**                    | 目录约定：`assets/sounds/` | —            | 未注明                                  | —   |
| **Xiao-MengFu/Crayon_Shin-chan_Desktop_Pet** | BGM + 动画音             | —            | "多媒体素材来自网络"                          | MIT |

一眼能看出的规律：**这些项目要么不用音效，要么就是"几个到十几个固定槽位 + 网上找的素材"**，  
没有一个（包括最火的）做过完整的音效体系 —— 音量档位、设备管理、事件级增益这些。

## 三、Shimeji 到底有没有声音

这是最容易被搜索结果误导的一点。中文下载站都在宣传"shimeji 桌宠内置丰富音效"  
（"点击桌宠或触发特定行为时播放趣味音效，如笑声、问候语"），但拆开看：

- **原版 Shimeji-ee**（Group Finity 的 Java 程序，`Shimeji-ee.jar` + `img/` + `conf/`）  
  的配置里**没有任何音频项**，行为靠 `actions.xml` / `behavior.xml` 描述，全程静默。
- 带声音的那几个（比如"神乐七奈 shimeji 桌宠"）说明里写得明明白白：
  > "这次用的本体是 **shimeji-ee 的改版**，有语音功能真是太棒了。**语音素材一部分来自狗妈战斗语音包**。"

所以结论是：**Shimeji 是"改版者往里面塞语音包"，本体压根没有音效层**。  
想从它身上抄"音效该怎么做"，抄不到东西 —— 它做的就是"塞一段角色语音"。

> 顺带一句：中文站那些"shimeji 桌宠官方版 v7.6"基本是套壳商业软件，  
> 和开源本体没关系，里面的"音效系统"也不具备参考价值。

## 四、最值得对照的一份：Bongo Cat 的音效规范

`luinbytes/bongocat` 是这次调研里**唯一一个把音效当成工程来做的**，而且它的选择和  
我们撞了大半。原文（仓库 README 的 Custom sounds 一段）：

> Drop WAV/OGG files into `sounds/default/`:  
> `slap.wav` / `slap_alt.wav` — alternating slap sounds  
> `combo.wav` — combo milestone  
> `combo_high.wav` — high-tier combo (50+)  
> `achievement.wav` — achievement unlocked  
> **Keep them under 500 ms and normalized to a consistent volume.**

逐条对照我们：

| Bongo Cat 的做法                                              | 我们的做法                        | 一致？     |
| ---------------------------------------------------------- | ---------------------------- | ------- |
| 播放后端 **pygame**（README 排错里写 "Confirm pygame is installed"） | **pygame**                   | ✅ 撞了    |
| 素材**短**（< 500 ms）                                          | 交互音 ≤ 1 秒                    | ✅ 同向    |
| **统一归一化音量**                                                | 峰值统一 0.85                    | ✅ 撞了    |
| 固定槽位名 + 拖文件即换                                              | `EVENTS` 定名字 + 丢 `<key>.wav` | ✅ 同一个思路 |
| 音效开关 + 音量（`sound_enabled` / `sound_volume`）                | ☑ 音效 + 轻/中/响                 | ✅ 一致    |
| 有 `generate_sounds.py` 自己合成                                | 我们从现成 CC0 包挑                 | ⭕ 只这点不同 |

**撞方案不是巧合**：Bongo Cat 是"按键就响一下"的高频场景，和"戳一下桌宠"一样，  
**延迟敏感 + 素材必须短 + 音量必须齐** —— 最优解自然收敛到同一个位置。  
它唯一和我们不同的"合成音效"，是因为它的音是敲鼓声，合成比找素材还省事；  
我们的音是抽卡、金币、闹钟，用现成素材更合适。

还有一点值得记：**Bongo Cat 的 README 排错里专门有一条 "No sound"**，  
让用户确认 pygame 装没装、音效开关开没开、`sounds/default/` 在不在。  
说明"没声音"是这个场景的高频问题 —— 我们的 `sfx.py` 用 `missing()` 列出缺哪些素材，  
方向一样，只是做得更靠前。

## 五、素材源怎么选

调研里几个来源被反复提到，按**授权风险从低到高**排：

| 来源                                                                                                  | 授权                         | 署名      | 适合                             |
| --------------------------------------------------------------------------------------------------- | -------------------------- | ------- | ------------------------------ |
| [Kenney](https://kenney.nl/assets)                                                                  | **CC0**（公共领域）              | 不需要     | 成套的游戏就绪音效：UI、撞击、RPG、赌场、Jingles |
| [Juhani Junkala · 512 Sound Effects](https://opengameart.org/content/512-sound-effects-8-bit-style) | **CC0**                    | 不需要     | 复古 8bit，开源游戏圈事实标准（9 万+ 下载）     |
| [Freesound](https://freesound.org)                                                                  | 逐条（CC0 / CC-BY / CC-BY-NC） | CC0 不需要 | 找某个特定音（73 万条，约一半 CC0）          |
| [Mixkit](https://mixkit.co/free-sound-effects/)                                                     | Mixkit 免费许可                | 不需要     | 成品感强：金币、闹铃、竖琴、卡牌               |
| Sonniss GDC Bundle                                                                                  | 免版税                        | 不需要     | 专业录音棚级，体积巨大                    |

两条提醒：

- **Freesound 是逐条授权的**（同一站里 CC0 和 CC-BY-NC 混着），下载前必须看清那一条。  
  CC-BY-NC 不能商用 —— 这是最容易踩的坑。
- **Mixkit 的唯一限制是不能把素材本身再分发**。随程序发布没问题，但别把  
  `assets/sfx/` 单独打包发出去。这条已经写进 `assets/sfx/README.md`。

我们的三个源（Kenney / Junkala / Mixkit）都在"不需要署名"那一档，  
省掉了给每个音效挂致谢的麻烦。

## 六、落到本项目

调研的净收益是**三个决定被验证了**：

1. **播放后端选 pygame 是对的** —— 另一个 Python 桌宠（Bongo Cat）也是它，  
   而且我们换它的理由（蓝牙设备常开、去掉每次开关设备的延迟）比它的理由更硬。
2. **"素材短 + 归一化"是这个场景的通行规范**，不是我们拍脑袋定的。
3. **不做"角色语音包"是对的** —— 那需要配音素材，且受众窄；通用动作音效覆盖面大得多。

没有改动的部分：素材来源保持 Kenney / Junkala / Mixkit 三家，  
每个事件的主选与备选见 `assets/sfx/README.md` 的表。
