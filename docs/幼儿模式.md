# 幼儿模式 · 设计与验收

给想玩电脑的小朋友用：**开了之后只有桌宠能点，桌面上的其他东西锁住**。
给小朋友玩的入口是右键桌宠 →「幼儿模式」。

代码在 `pet/kids.py`（遮罩与控制器）和 `pet/keyblock.py`（严格档的键盘钩子）。

---

## 一、它到底靠什么"锁"

不是拦截消息、也不是给桌面贴一层 shell 扩展，而是一条**窗口层次**：

```
最上层   桌宠 · 小游戏 · 卡册 · 背包 · 番茄钟对话框     ← 鼠标点得到
中间层   全屏遮罩（铺满所有显示器的那块半透明玻璃）      ← 其余点击全落这儿，吞掉
最下层   桌面图标 · 任务栏 · 别的程序                    ← 够不着
```

* 遮罩是**独立的全屏置顶窗口**，无边框、不进任务栏、不进 Alt+Tab（用 `Qt.Tool`）。
* 桌宠没有画在遮罩里面，而是被**单独抬到遮罩之上** —— 所以点桌宠的鼠标事件由
  系统直接送给桌宠窗口，压根不经过遮罩。这比自己转发事件可靠得多：
  转发要处理拖动、右键、滚轮、双击，漏一样就多一个说不清的怪现象。
* `KidsMode.keep_above()` 每 **600 毫秒**重排一次顺序。必须定时重排，因为
  任务栏会时不时把自己重新抬高（点它、或收到 shell 通知时）。
* **顺序不能反**：`raise_()` 的含义是"抬到同一层里最上"，而任务栏也是置顶窗口。
  先抬遮罩才能盖住任务栏，后抬桌宠/游戏才能盖住遮罩。

遮罩的底色 `QColor(12, 16, 26, 150)` —— **alpha 必须大于 0**：置顶的透明窗口是
**按像素 alpha 判定命中**的，全透明的地方鼠标会直接穿过去，那就等于没锁。

## 二、两档的差别只有键盘

| | 鼠标点别的东西 | Win / Alt+Tab / Alt+F4 | 代价 |
|---|---|---|---|
| **安全档** | 完全挡住 | ❌ 拦不住 | 无。纯 Qt 窗口层次，不碰系统 API |
| **严格档** | 完全挡住 | ✅ 挡住 | 低级键盘钩子；杀软可能报警、钩子出问题会顿键盘 |

系统级的切换手势（Win、Alt+Tab）**不走窗口，走的是系统**，遮罩天生碰不到它们。
要拦住只能用 `SetWindowsHookEx(WH_KEYBOARD_LL)`：系统会在**任何一个按键送到目标
窗口之前**先把这次按键交给我们的回调，返回非 0 就是"吃掉"。

**吃掉哪些键**（`pet/keyblock.py`，纯函数 `should_block`，可脱机测）：

* 无条件吃：左/右 `Win`、菜单键
* 按住修饰键才吃：`Alt+Tab`、`Alt+Esc`、`Alt+F4`、`Alt+Space`、
  按住 Ctrl 的 `Esc`（含 `Ctrl+Shift+Esc` 任务管理器）
* **一律放行**：单独的 Tab / Esc / F4 / 空格、Shift+Tab、所有字母数字

不放行正常按键是硬要求：锁得太死会连小游戏和密码小键盘都用不了，那这个模式
就没有意义了。

**为什么不做成"一个开关 + 一个严格档勾选"**：两档的代价不一样（严格档要装钩子），
而用户是按"今天要锁到多死"现场决定的，不是按"设置"。所以菜单里给两个平级入口。

## 三、安全设计（改代码之前先读这一节）

1. **绝不写进存档**。`cfg` 里只有 `kids_passcode`，没有任何"正在锁定"的字段。
   桌宠是会被任务管理器结束掉的常驻程序 —— 一旦把锁定状态持久化，异常退出后
   重启就会自己锁上，用户会以为电脑坏了。**重启即解除**，这是刻意的。
   冒烟测试有一条断言盯着"存档里只有一个 kids 字段"。
2. **没设密码不许进**（`enter` 返回 `"fail"`）。所以不存在"进去了但退不出来"。
3. **退出时必须卸钩子**。`KidsMode.shutdown()` 在 `main.quit()` 里最先调用。
   钩子是系统级的，程序没了它还挂着，症状是"Win 键莫名其妙失效"，
   而用户完全联想不到是桌宠。
4. **装不上就降级 + 明说**。`strict=True` 而钩子没装上时会**降级成安全档继续开**，
   并且弹窗说明 —— 不说的后果是用户以为锁死了、其实 Win 键还能按，他不会去验。
5. **锁着时右键菜单只留"玩桌宠"那几块**（`PetWindow.kids_locked`，白名单式）。
   特别是砍掉「退出」「藏进托盘」和幼儿模式入口本身：否则小朋友右键一下
   就能自己开门，或者把桌宠藏进托盘搞得自己没得玩。
   用**白名单**而不是黑名单 —— 以后新加一个菜单项，默认不会漏进幼儿模式。
6. **退出时把临时改过的设置还回去**：桌宠的"始终置顶"、以及被临时加上置顶的
   游戏/卡册窗口（不还的话，小朋友玩过之后那些窗口会一直浮在最上层，
   用户找不到原因）。

## 四、兜底：Ctrl+Alt+Del

它是 Windows 的**安全注意序列**，由系统内核直接处理，**任何用户态钩子都拦不住**。
万一卡在幼儿模式里出不来，按它 → 任务管理器 → 结束程序即可。

因为这条兜底一定有效，代码里**不需要**再留"紧急自救热键"，也不需要
"进程崩溃时自动解锁"这类机制 —— 少一个机制就少一处会出错的地方。

## 五、密码忘了怎么办

密码是**明文**存在 `config.json` 的 `kids_passcode` 里的。刻意如此：

* 忘了 → 打开 `config.json` 看一眼；
* 或者把它改成空字符串 `""` → 下次开启时会重新让你设一个。

存哈希看着"更安全"，实际是把唯一的后路堵死：这是个**家长给自己用的锁**，
不是防外人，唯一的失败模式是"家长把自己锁在外面"。

## 六、怎么验收（真机）

离屏测试验不了"遮罩是不是真盖住了桌面"——那要靠肉眼。步骤：

1. 双击 `run.bat`，等桌宠出现。
2. 右键桌宠 →「幼儿模式」→「开启 · 安全（只锁鼠标）」，第一次会让你设 4 位密码。
3. 确认这几件事：
   - 整个桌面变暗，桌宠还亮着、还能拖着走；
   - 点桌面图标、点任务栏、右键桌面 → **全都没反应**；
   - 右键桌宠 → 菜单里**没有**「退出」「藏进托盘」「幼儿模式」，
     但「逗它玩」「卡册」「一起玩游戏」都在；
   - 点「一起玩游戏」→ 游戏窗口**浮在暗色遮罩之上**，玩得动；
   - 按住屏幕右上角约 1.5 秒 → 弹出小键盘 → 输密码 → 遮罩消失，桌面恢复。
4. 再试严格档：
   - 按 `Win`、`Alt+Tab`、`Alt+F4` → **都没反应**（严格档）；
   - 在游戏里敲方向键、在密码键盘上敲数字 → **正常**；
   - 退出后按 `Win` → 开始菜单正常弹出来（说明钩子卸干净了）。
5. 最后验"绝不落盘"：开着幼儿模式直接**用任务管理器结束 python 进程**，
   重新启动 → 应该是**普通的、没锁的**桌宠。

`tools/smoke_test.py` 的「幼儿模式」段（60 条）会验掉其中能离屏验的部分。

## 七、已知边界（别以为它万能）

* **安全档挡不住系统级键盘手势**。这是刻意的取舍：不装钩子就没有任何副作用，
  代价是 Win / Alt+Tab 还能用。要挡就选严格档。
* **任务栏是"被盖住"而不是"被藏起来"**。遮罩每 600 毫秒重排一次层级，
  正常情况盖得住；但任务栏在自我抬高的一瞬间理论上可能露一下可点的空档。
  要彻底解决得调 `FindWindow("Shell_TrayWnd") + ShowWindow` 去藏它 ——
  那属于改系统窗口状态，崩了会让任务栏一直躲着，所以没做。
* **杀软可能对严格档报警**。低级键盘钩子和键盘记录器是同一个系统接口。
  本项目**只拦不记**（回调里只查表 + 返回，不落盘、不出网），
  但启发式扫描看不到这一点。打包分发时如果被拦，选安全档，或者加白名单。
* **只能锁住鼠标和键盘这两条路**。真有小朋友去按机箱电源键，那谁也拦不住。
