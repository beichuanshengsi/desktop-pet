## 一、要解决的问题

小卖部（v2.1.0）上了之后，金币的**唯一**出口是三样消耗品 —— 肉干 12 / 玩具球 18 /
大餐 30，全是一次性花完就没的东西。你的原话是"**没有值得攒钱的东西**"。

所以这一版的全部目标就一条：**给金币一个长期目标**，同时不破坏已有的养成节奏
（三值衰减、小卖部、四个小游戏）。

## 四、存档新增字段（`config.json`）

```jsonc
{
  "cards":        { "c009": 2, "c054": 1 },   // 卡 id -> 拥有张数（重复的也留着）
  "frag_low":     0,                          // 低级碎片
  "frag_high":    0,                          // 高级碎片
  "equipped":     ["c009"],                   // 装备栏（卡 id 列表）
  "week_stamp":   "2026-W41",                 // 本周标识，不等就说明跨周了
  "weekly_used":  { "传说": 1 },              // 本周各档已兑换次数
  "low_convert_used": 0,                      // 本周低换高已消耗的低级碎片数
  "dup_streak":   { "传说": 2 }               // 保底计数：连续撞重复几次
}
```

**老存档能直接升级**：所有字段都有默认值，缺字段就读默认值，不会崩。
`Config.load()` 原本只认 bool/int/float/str/dict —— 这轮补了 **list**，
否则 `equipped` 会被静默丢掉（不报错，只是装备全没了）。

## 五、规则一览（写进代码的那份）

| 项 | 值 |
|---|---|
| 池子 | 104 张：普通 53 / 稀有 26 / 史诗 18 / 传说 7 |
| 出率 | 普通 62% / 稀有 26% / 史诗 10% / 传说 2% |
| 单抽价 | 60 金币 |
| 重复卡 | **不自动转碎片**，留在册里由玩家手动分解 |
| 分解 | 需留一张。普 2 低 / 稀 6 低 / 史 4 高 / 传 10 高 |
| 兑换价 | 普 4 低 / 稀 24 低 / 史 16 高 / 传 30 高 |
| 每周额度 | 普 16 / 稀 5 / 史 2 / 传 1（跨周不累积） |
| 撞重复返还 | 按分解价部分返还（净亏 = 价 − 返还 > 0） |
| 保底 | 同一档连续 3 次撞重复 → 下次必出未拥有 |
| 低换高 | 5:1，每周上限 34 个低级碎片 |
| 装备 | 5 槽，每 3 周解锁 1 个（第 13 周满） |
| 加成 | 普 +1% / 稀 +2% / 史 +3% / 传 +5%（金币），硬顶 +20% |

**预期节奏：26 周（约半年）集齐 104 张**，传说 25 / 史诗 19 / 稀有 15 / 普通 10 周。

## 六、验证

| 命令 | 项数 | 结果 |
|---|---|---|
| `python tools/smoke_test.py` | 424 | ✅ 全过（**原有功能一条没坏**） |
| `python tools/check_cards.py` | 51 | ✅ 全过（出率 2 万次抽样等） |
| `python tools/verify_album_ui.py` | 24 | ✅ 全过 + 出 `reports/*.png` 截图 |
| `python tools/typecheck.py` | 0 error | ✅ pyright 全量扫过 |

**这轮真的抓到并修掉一个 bug**：保底给出新卡之后 `dup_streak` 没归零，
下一轮立刻又触发保底 —— 实际效果是"每两次必出一张新卡"，比设计的快一倍。
是 `check_cards.py` 里"保底后计数该归零"那条断言把它揪出来的。

## 七、遗留 / 可以继续做的

1. **每局产出还是按老汇率**（`COIN_PER_SCORE = 10`，一局 200~800 分 → 20~80 金币）。
   模拟时假设的"每局 80 金币"对应 800 分那一档，也就是**打得好的局才够抽一次多**。
   如果要让"一局一抽"更普遍，把 `COIN_PER_SCORE` 提到 20 即可 —— 但那会连带动
   小卖部的价格感，属于另一轮调参。
2. **装备只加金币，没做异质效果**（不给碎片加成、不给免费抽）。这是刻意的，
   理由见 CHANGELOG 的"三个刻意的设计决定"第 3 条。要做的话得单独建模。
3. `FACTS.md` 本轮**没动**（它是验收证据台账，这一版的证据在 `reports/` 和
   上面那三条命令里）。
4. 卡册窗口高度约 713 逻辑像素，1080p 下没问题；150% 缩放的 768p 屏上会接近满屏
   （已加"贴顶摆放"兜底，但没做滚动）。
