# 聊天功能（v2.10.0）

给桌宠接一个会说人话的嘴：点它聊天、饿了讨饭、被甩出去抱怨。
目标是**像网上那些 AI 桌宠**，但保留这个项目原来的底线 ——
不联网也不能坏。

---

## 一、两挡：在线 / 离线

| | 触发条件 | 说什么 | 代码 |
|---|---|---|---|
| 在线挡 | `config.json` 里 `chat_api_key` 非空 | DeepSeek 按「人设 + 状态 + 最近的事 + 最近对话」现编 | `chat.call_deepseek()` |
| 离线挡 | 没 key / 断网 / 超时 / 401 / 402 / 返回畸形 | 从 `chat.OFFLINE_LINES` 按场景挑一句 | `chat.pick_offline()` |

两条挡走**同一个入口**（`ChatController.user_send` / `.event`），
所以"没配 key"在用户看来不是错误，只是这只狗嘴笨一点。

> 为什么不只做在线版：安装包是发给别人用的，对方多半没有 key。
> 只做在线的话，那些人点开聊天看到的是一个报错 —— 那是故障，不是功能。

---

## 二、文件与职责

| 文件 | 管什么 | 不碰什么 |
|---|---|---|
| `pet/chat.py` | 纯逻辑：人设、提示词拼装、对话记忆、冷却、离线台词、HTTP 出口 | Qt、窗口 |
| `pet/chatui.py` | `ChatWorker`（QThread）、`ChatBubble`（气泡）、`ChatWindow`（聊天窗口）、`ChatSettingsDialog`、`ChatController`（调度） | 不 import `window`（用鸭子类型） |
| `pet/window.py` | 只挂三个入口：`open_chat()` / `chat_settings()` / `set_chat_enabled()`，以及六处 `chat.event(...)` | 不认识 API key |
| `pet/menu.py` | `add_chat()`：状态行 + 两个入口；`TOGGLES` 里加「主动搭话」 | 不管请求 |
| `pet/config.py` | 三个字段：`chat_enabled` / `chat_api_key` / `chat_persona` | 不存聊天记录 |

**聊天记录不放在 `config.json`**：那边是"用户选了什么"，这边是"聊过什么"。
`config.json` 手滑删掉等于重置整个桌宠；`chat_log.json` 删掉只丢记性。

| 文件 | 位置（打包后） | 内容 |
|---|---|---|
| `config.json` | `%APPDATA%\DesktopPet\` | 开关、key、人设 |
| `chat_log.json` | 同上 | 最近 40 轮对话 + 最近 20 条事件 |

## 三、事件与冷却

```python
EVENT_COOLDOWNS = {
    "hungry": 600,      # 饿了讨饭
    "flung": 20,        # 被甩落地
    "feed": 180,        # 被喂（肉干 / 免费那一口）
    "feast": 5,         # 豪华大餐：只防连点
    "poke": 300,        # 被逗
    "nap": 600,         # 被安排睡
    "night": 8 * 3600,  # 深夜（另外还有"一晚一次"的按天记）
}
```

**所有冷却必须 > 0**（冒烟测试里有一条断言盯着）。挂点：

| 事件 | 挂在哪 |
|---|---|
| `hungry` | `PetWindow._steer_if_hungry()`，只在**第一次动身**那一刻 |
| `flung` | `PetWindow._end_fling()` |
| `poke` | `PetWindow.poke()` / `use_item()` 里玩具球那条 |
| `feed` | `PetWindow.feed()` 免费那一支 / `use_item()` 里吃的 |
| `feast` | `use_item()` 里**豪华大餐**（商品表声明 `event="feast"`）|
| `nap` | `PetWindow.nap()` |
| `night` | `ChatController.maybe_night()`，由 `_advance()` 每帧调、内部 30 秒才查一次 |

> **贵的动作不该被便宜的冷却吞掉**：`feed` 那 180 秒是给"随手一口"防连点的，
> 豪华大餐 30 金币一次，跟它共用一个冷却就会出现"喂了大餐它一句话没有"
> （v2.10.2 修的就是这个）。所以商品表里多了一栏 `event`，贵的自己一类、
> 自己的台词、几乎不设冷却。
>
> **不做随机定时**。v2.2.0 把"鼠标划过弹状态卡片"整个删掉了，理由写在
> `pet/panel.py` 开头：桌宠常驻桌面，随机/高频触发就是噪音。
> 主动搭话只挂在**真实发生的事**上，这是这条教训的直接产物。

## 四、常见的三件改动

### 换人设

菜单「聊天 → 聊天设置…」，把「人设」那段字整段改掉（留空 = 用
`chat.DEFAULT_PERSONA`）。改完**下一条消息就生效**，不用重启。

### 换 key

同上，key 输入框粘贴新的。key 是**明文**存在 `config.json` 里的 ——
这是你自己能手改的文件，存哈希只会在换 key 时添堵。

### 加一句离线台词

1. 打开 `pet/chat.py` 的 `OFFLINE_LINES`，往对应场景的元组里加一条；
2. 每个场景**至少留 3 句**（测试会查）：只有一句时"不重复上一句"就没得挑；
3. 语气得跟默认人设一致（**傲娇但心软，不许带刺**）—— 在线离线是同一只狗，
   不能断网后突然变乖。冒烟里有一条黑名单断言，写进「良心不会痛 / 不然没完 /
   啃鼠标 / 眼睛还要不要 / 喂！ / 算你有良心」会直接失败。

### 气泡跟着谁走

`ChatBubble.speak(text, anchor, anchor_getter=None)`：给了 `anchor_getter`
就按 `BUBBLE_FOLLOW_MS`（60ms）轮询重定位，不给就只在开口那一刻摆一次。
`ChatController._speak()` 传的是 `self.anchor_rect`（桌宠当前 `frameGeometry()`），
所以气泡会一直贴着头顶；气泡 `hide()` 时定时器自动停，不留后台轮询。

### 加一类事件

1. `EVENT_COOLDOWNS` 加一项（正数）；
2. `EVENT_LABEL` 加中文说法（prompt 里用）；
3. `OFFLINE_LINES` 加这个场景的台词（不加会退到通用台词，不崩）；
4. 在 `ChatController.event()` 那段 `clue` 里补一句给模型看的描述；
5. 在 `PetWindow` 对应动作末尾加 `self.chat.event("你的标识")`；
6. 冒烟测试的「聊天」段补一条断言。

## 五、隐私与钱

- 只有点开聊天、或触发上面那六类事件时才会发请求；**不读屏幕、不读文件**，
  发过去的就是：人设 + 三个状态值 + 金币 + 动作名 + 钟点 + 最近几轮对话；
- 一句回复 `max_tokens=120`，按 DeepSeek 的价目表是几分钱的事，
  日常逗狗一个月**几块钱**量级；
- key 只存在本机，不上传到任何第三方（除了 DeepSeek 自己的接口）。
