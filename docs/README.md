# docs/ —— 设计文档

放这个项目的书面材料。工作区文件（`desktop-pet.code-workspace`）已经把本目录单独挂成一个根，
在 VS Code 侧边栏里能直接当第二棵树看。

## 放什么

| 文件 | 说明 |
|---|---|
| `需求规格说明书.docx` | 已生成，见下方"已有材料" |
| `状态机设计.md` | 状态转移表、触发条件、超时规则 |
| `物理参数.md` | 重力/摩擦/弹性的取值与调参记录 |
| `测试记录.md` | 冒烟测试覆盖项 + 手工测试清单 |

## 小游戏的规则写在哪

没有单独的设计文档 —— 数值就写在代码常量的位置上，改一个数只改一处：

| 游戏 | 文件 | 说明 |
|---|---|---|
| 弹跳得分 | `game/minigame.py` | 方块布局、起跳初速、60 秒单局、通关加时 |
| 接狗狗 | `game/catcher.py` | 血量上限、扣血规则、连击奖励、难度爬升、两条出怪保底 |
| 共用部分 | `game/common.py` | 窗口尺寸、HUD 高度、地面厚度、中文字体回退链、结算浮层 |

写进报告时建议直接引 `game/catcher.py` 开头那段 docstring —— 那里把
"为什么复用 `Motion`""为什么缺素材也能玩""为什么难度只看存活时间"三个取舍都写了。
