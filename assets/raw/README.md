# assets/raw/ —— 原始素材暂存 + 素材规格说明

把你**下载到的、还没加工过的**素材丢在这里。程序**不会**读这个目录，
加工完的成品才进 `../pet/` 或根目录的 `custom_pet/`。

---

## 〇、最省事的做法：全部丢进 inbox/

不想管哪个文件是哪个动作，就**全部丢进 `inbox/`，不用改名也不用分类**：

```bash
python tools/intake.py            # 只看方案，不动文件
python tools/intake.py --apply    # 确认无误后落位
```

它会自己判断每个文件是什么，分别送去该去的地方：

| 认出来的东西 | 去哪儿 |
|---|---|
| 宠物动图 / 表情包 / 透明帧序列 | `custom_pet/`，按 `<状态>_<序号>.png` 命名 |
| 背景图（`bg` / `背景`） | `assets/game/bg_bounce.png` 或 `bg_catch.png`（按文件名认是哪个游戏的） |
| 方块、球 | `assets/game/` |
| 图标（`icon` / `图标`） | `assets/icon.png`，并自动补出多尺寸 `icon.ico` |
| 音效（`.wav` / `.mp3`…） | `assets/sfx/` |
| 字体（`.ttf` / `.otf`） | `assets/fonts/` |
| 视频、PSD | 拒绝，并告诉你为什么 |

> **背景图有两个**（两个游戏各一张），所以不再统一写成 `bg.png`。
> 文件名里带「弹跳 / 舞台 / 粉」→ `bg_bounce`；带「接 / 蓝天 / 草地 / 云」→ `bg_catch`；
> 都没命中就看哪张还缺 —— 缺哪张补哪张。**背景图不能直接拷**：原图是竖版大图，
> 落位时会按地平线裁成游戏窗口尺寸（780×580，地平线在 y=534）。裁歪了用
> `python tools/prep_bg.py 原图.png --name bg_catch --ground 0.78 --preview` 重裁。

**图标不用你操心**：有宠物素材入库时，`intake.py` 会顺手从它裁出头部更新
`assets/icon.png`（托盘 / 小游戏窗口 / 任务栏共用那个），免得出现"桌面上的狗换了、
托盘上还是上一只"。想自己指定图标，就把 PNG 丢进来、文件名里带 `icon` 或 `图标`，
会用你那张，并自动补出 `.ico`。单独重做图标：`python tools/make_icon.py --preview`。

**动作是这么认的**：先看文件名里的关键词（`发呆`→idle、`跑`→walk、`被拎`→drag、
`掉落`→fall、`逗他玩`→poke、`喂一口`→feed）；认不出来就看动图的运动轨迹 ——
横向位移占优 = 走路，纵向往返 = 原地起跳式的互动反应（poke），
抬上去不回位 = 被拎起来，一路往下 = 下落。

**猜错了不用改名**，用 `--map` 当场指定：

```bash
# 文件名里含「晃脚」的当待机，含「害怕」的当被拎起来
python tools/intake.py --map 晃脚=idle --map 害怕=drag --apply

# 某套素材看着偏小/偏大，单独微调缩放
python tools/intake.py --zoom 晃脚=1.15 --apply

# 新素材的狗画得比老素材大/小，直接钉死缩放比，让它和已有动作一样大
python tools/intake.py --scale 逗他玩=0.56 --scale 喂一口=0.44 --apply

# 素材自带弹跳（蹦蹦跳跳的走路、发抖），要保留腾空感
python tools/intake.py --motion keep --apply

# 这批素材的原图是朝左画的（脸在左边），要告诉程序一声
python tools/intake.py --face left --apply
```

> **`--face` 为什么必须存在**：程序只知道"往哪走"，不知道"素材画的是哪一边"。
> 两者对不上，狗就会**倒着走** —— 从代码上看不出任何毛病，只有眼睛能发现。
> 所以朝向存进 `custom_pet/facing.json`（跟贴图放一起），绘制时只有
> "行走方向 ≠ 素材朝向"才水平镜像。判断方法：**看头在哪一侧**。
> 设错了不用重新入库，`python tools/set_facing.py flip` 或右键桌宠
> → `左右翻向` 就能翻过来。没声明时按默认**朝右**处理。

> **为什么需要 `--zoom`**：几套素材一起入库时，脚本会取一个**跨素材共用**的缩放比
> （取各套"刚好放进画布"的最小值）。这是为了不让角色在切换动作时突然变大变小 ——
> 同一只角色的几套表情包，狗在原始素材里本来就一样大，各套各自"缩放到填满"的话，
> 带道具的那套（比如狗坐在长凳上）并集更大、被缩得更小，一拖起来就"长大"了。
> 代价是每套都留了一点余量，想让它更大就单独给 `--zoom`。
>
> ⚠️ **`--zoom` 只管本次投递的那几套素材。** 分两次投递（先入 idle、过几天再入 walk）
> 时，两批各算各的缩放比，尺寸会不一致。补救办法有两种：
> * 用 `--scale 关键词=值` **直接钉死**这一套的绝对缩放比（推荐：可读、可复现）；
> * 或者用 `--zoom 关键词=倍数` 在本批基准上放大/缩小。
>
> 目标值怎么定：把候选缩放比各渲染一版，和已入库的 `idle_00.png` / `walk_00.png`
> 并排看，狗一样大就对了。量像素时**按角色身体颜色量，别用整体包围盒** ——
> 装饰性的虚线、道具、旁边的第二只角色、飞出去的花，都会混进包围盒，
> 量出来的数字看着一致、其实是装饰的宽度。

> **`--motion` 怎么选**：默认 `flatten` 让每一帧的脚都落在同一条地平线上，
> 素材自带的位移被抹平，位移完全交给窗口。这对"原地做动作"的素材是对的
> （坐在凳子上晃脚、躺着打滚）—— 两处位移叠加会让它看起来在抽搐。
> 但**自带弹跳的素材用 flatten 就废了**：腾空帧的脚会被硬按到地上，
> 蹦跳变成"脚踩地原地伸缩"。这种素材用 `--motion keep`，
> 所有帧共用一个坐标系，只把水平居中、垂直位移原样保留。
> 判断方法：量一下各帧内容底边的 y 值 —— 恒为同一个数就是已经被压平了。

执行完原文件会挪进 `_archive/<时间戳>/`，不会重复处理。

> ⚠️ **`_archive/` 里是你的原始素材，删了就没了。**
> 它是唯一保留"下载来的原图"的地方（`custom_pet/` 里是加工后的成品，
> 尺寸和抠底都已经改过，回不去原图）。要清理时**按时间戳只删本次那一层子目录**，
> 不要整个删掉 `_archive/`。这件事已经真实发生过一次：一次测试后的清理把用户的
> 三个原始 GIF 一起删了，只抢救回加工版快照（见 `_snapshots/README.md`）。

## 〇.5、`_library/`：整批下载的素材库（只做归档，不参与加工）

`inbox/` 适合"几个文件、马上加工"。但有时一次下载的是**一整个素材包**
（比如这次从爱给网一次拉了 198 个 GIF）—— 那不适合全丢进 `inbox/`：
`inbox/` 会被清空、加工完挪进 `_archive/`，原始素材就散了。

这种情况放 `_library/`，按**批次**建子目录：

```
assets/raw/_library/
├── 0921_1530_线条小狗GIF/        198 个 GIF（爱给网「线条小狗」系列）
└── 0921_1530_背景图/             2 张 2848×1600 背景大图
```

约定：

* 子目录名用 `日期_时刻_说明`，**一眼看出是哪一批、什么时候下的**。
* `_library/` 是**原始素材的唯一归档处**，程序不读它，`intake.py` 也不动它。
  要加工时**从里挑文件**跑 `prep_sticker.py`（挑哪几个、用什么参数见下文）。
* 挑素材前先做**联系表**（把整批缩略图拼成一张大图）快速过一遍，
  比一个个打开快得多；再看**动画过程**判断动作类型（走路要有横向位移，
  只看单帧会认错）。
* 整批素材里通常**大部分是透明底表情包**，但也有"实景照片底"的混在里面 ——
  实景底抠不干净，**当桌宠贴图会带一块背景**，挑的时候要排掉。
* `.gitignore` 排除了 `_library/`（体积大、版权归原作者），换机器要重新下载。

> **当前这批素材的挑选结论**记在 `custom_pet/README.md`（桌宠用了哪 5 个）
> 和 `assets/game/README.md`（游戏用了哪 4 个）；参考图存在
> `reports/` 里，重挑时对着看。

## 一、你不需要自己加工

拆帧、抠底、缩放到统一尺寸、按规范重命名 —— 这四件事都由
`tools/prep_sticker.py` 自动完成（`intake.py` 底层调的就是它）。
**你只要把原始文件丢进 `inbox/` 就行。**

支持的输入：

| 你给什么 | 怎么处理 | 备注 |
|---|---|---|
| 一个 GIF / APNG / WebP 动图 | 逐帧拆开 | 最常用，一个表情包就是一个动作 |
| 一个文件夹的图片 | 按文件名顺序当帧 | 已经抠好的透明 PNG 序列 |
| 一张精灵表（多格拼图） | 按网格切开 | **要告诉我几行几列**（走 `prep_sticker.py --sheet`） |
| 一张静态图 | 单帧 | 也能用，只是不会动 |

不支持的：**JPG**（没有透明通道）、视频、Live2D 模型。

## 二、成品规格：每一帧长什么样

程序只认 `assets/pet/` 下的 `<状态>_<序号>.png`，比如 `idle_00.png`、`idle_01.png`。
序号从 `00` 开始，两位数字。

| 要求 | 说明 |
|---|---|
| **格式** | 必须是 PNG，必须带透明通道（alpha）。带白底的图会在桌面上显示成一个方块 |
| **形状** | 正方形。标称 128×128，**但建议给 256×256 或 512×512** —— 程序会缩小，给大不给小 |
| **裁边** | 透明边会被自动裁掉，不用自己裁 |
| **锚点** | 每帧的**脚底**（内容最低点）必须落在画布内同一个高度，距底边留一点空隙 |
| **朝向** | 素材里角色**头朝哪一侧**，要在 `custom_pet/facing.json` 里声明（`{"base":"left"}` 或 `"right"`）。程序据此决定往哪边走要不要镜像；没声明按默认**朝右**算 |
| **居中** | 角色在画布里水平居中，否则转身时会左右横跳 |

> **锚点、居中、朝向这三条程序都推不出来** —— 它不知道哪只脚才是脚，也看不出
> 狗脸朝哪边。走路时宠物上下弹跳、转身时左右横跳、走起来倒着滑，就是这三条没做到。

## 三、六个动作状态

| 状态 | 文件名 | 建议帧数 | 程序播放帧率 | 必须吗 |
|---|---|---|---|---|
| `idle` | `idle_00.png …` | 4–8 | 7 fps | **必须有** |
| `walk` | `walk_00.png …` | 4–8 | 11 fps | 建议有 |
| `drag` | `drag_00.png …` | 2–4 | 13 fps | 可选 |
| `fall` | `fall_00.png …` | 2 | 7 fps | 可选 |
| `poke` | `poke_00.png …` | 12–24 | 12.5 fps | 可选（右键「逗它玩」） |
| `feed` | `feed_00.png …` | 12–24 | 10 fps | 可选（右键「喂一口」） |

帧数怎么估：**帧数 ÷ 帧率 = 这段动画循环一次要几秒**。
比如 idle 想要"2 秒一次缓慢呼吸"，就用 7 fps × 2 秒 ≈ 14 帧，或者 8 帧放慢些。
帧数不够也没关系，程序会循环播放，只是动作会变快。

`poke` / `feed` 这两个一次性动作是**按素材自己的长度演的**：窗口进动作时会把时长设成
"这套素材的帧数 ÷ 上表的帧率"，播完一圈自动回 idle。所以素材有几帧就演多久，
换素材不用改代码。帧率最好和素材 GIF 的帧间隔对得上（80ms 一帧 → 12.5 fps，
100ms 一帧 → 10 fps），否则会看着忽快忽慢。

**缺状态不会崩。** 缺的那个状态会自动拿 idle 的帧来顶，桌宠照常显示，
只是走路时没有走路动作。所以最省事的起步方案是：**只给 idle。**

## 四、找素材的建议

- **想省事**：找一个循环动图（发呆、晃尾巴、眨眼）当 idle，这一个就够了
- **想要好效果**：找同一角色的多套表情 —— 发呆的 / 跑动的 / 被拎起来的 / 掉落的
- **表情包的通病**：一个表情包是"一个梗"，不会包含行走、下落这些动作。
  硬凑不齐时，缺的动作让程序用位移和缩放补，比用不同角色硬拼自然
- **背景**：优先找**纯色底**或已经抠好透明底的。白底 GIF 加 `--auto-key` 能抠干净；
  背景是照片、渐变、有噪点的，抠不干净，得先手动处理
- **版权**：交作业用的素材自己确认一下来源。这个目录已经在 `.gitignore` 里排除了
  （只保留 `README.md` 和空的 `inbox/`），不会跟着项目走

## 五、微信表情怎么变成文件

**走微信自带的导出功能，别去翻缓存目录。**

### 正确做法：聊天窗口右键另存为

1. 打开任意聊天窗口（「文件传输助手」最方便）
2. 把想要的表情发进去 —— 在表情面板里点一下，或从聊天记录里找到它
3. **右键那个表情 → 另存为** → 存出来是一个 `.gif`
4. 把存出来的文件丢进 `assets/raw/`

### 为什么不能直接去文件夹拷

微信的表情缓存在：

```
Documents\WeChat Files\<wxid>\FileStorage\CustomEmotion\<两位十六进制>\<32位哈希>
```

但这些文件**全部是加密的**：文件头是 `V1MMWX`，既不是 PNG 也不是 GIF，
看图软件和图像库都打不开。本机实测 3765 个文件无一例外，所以这条路走不通。

### 更省事的办法

如果那个表情属于**知名 IP 的成套表情包**，直接在网上搜同款 `.gif` 下载，
比从微信里一个个导出快得多，而且通常是原图质量。

### 挑几个就够

不用导出一整套 —— `idle` 是唯一必须的，挑 1~2 个最能代表角色形象的给我就行。

## 六、加工命令（给我文件后我跑，你想自己跑也行）

```bash
# 白底 GIF 表情包 -> 待机动作
python tools/prep_sticker.py assets/raw/猫猫发呆.gif --state idle --auto-key

# 4x4 精灵表 -> 行走动作
python tools/prep_sticker.py assets/raw/sheet.png --state walk --sheet --cols 4 --rows 4

# 已抠好的透明 PNG 序列目录
python tools/prep_sticker.py assets/raw/frames_drag --state drag

# 写进用户目录而不是内置目录（不污染项目文件，程序优先读它）
python tools/prep_sticker.py assets/raw/猫猫发呆.gif --state idle --auto-key --custom

# 小游戏素材（写进 assets/game/，前缀就是 --state 的名字）
python tools/prep_sticker.py 小黄狗.gif --state catcher --game --size 160
python tools/prep_sticker.py 小白狗.gif --state puppy_a --game --size 96 --keep 10

# 背景大图 -> 裁成游戏窗口尺寸（地平线对齐 GROUND_Y）
python tools/prep_bg.py 大图.png --name bg_catch --ground 0.78 --preview
```

常用参数：

| 参数 | 用途 |
|---|---|
| `--auto-key` | 自动探测四角底色并抠图（**白底素材必加**） |
| `--key-color "#RRGGBB"` | 底色不是纯白时手动指定 |
| `--tolerance 40` | 抠图容差，抠不干净就调大 |
| `--size 256` | 输出边长，默认 128 |
| `--scale 0.5` | **直接钉死绝对缩放比**（素材里角色画得大小不一时用，见上文 `--zoom` 的说明） |
| `--anchor bottom` | 以内容底边为锚点（桌宠站立用；游戏落体用默认的 `center`） |
| `--motion keep` | 保留素材自带的位移（蹦跳走路、发抖；默认 `flatten` 会把脚压平） |
| `--no-trim` | 不裁透明边 |
| `--pad 8` | 脚底距底边的空隙，想让自定义帧和内置帧站在同一条地平线上就调它 |
| `--keep 8` | 最多保留 8 帧（GIF 帧太多时用） |
| `--custom` | 输出到 `custom_pet/`，不覆盖内置素材 |
| `--game` | 输出到 `assets/game/`（小游戏素材） |

## 七、命名建议

丢进 `inbox/` 的话**不用改名**，动作由脚本猜。但如果想让它一次猜对（或者你打算手工跑
`prep_sticker.py`），文件名里带上动作最省事：

```
assets/raw/inbox/
├── 狗勾发呆.gif              -> --state idle
├── 狗勾跑动.gif              -> --state walk
├── 狗勾被拎起来.gif           -> --state drag
└── 狗勾掉落.gif              -> --state fall
```

一个动作给了多个文件时，脚本会警告你 —— 如果不是同一个角色，
它们会被连在一起播放，画面会中途"变脸"。
